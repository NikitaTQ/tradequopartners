# TradeQuo Partner Program: сайт

Статический сайт без сборки. Всё, что уходит на хостинг, лежит в `site/`.

```
site/
  index.html                 лендинг (Partner Program v2)
  commission-plans/ dashboard/ marketing-hub/ academy/ success-stories/
                             концепт-страницы, у каждой свой URL
  embeds/                    3D-блоки и ролики (iframe, грузятся при подходе к экрану)
  vendor/                    three.js и React — свои копии, без внешних CDN
  assets/css/site.css        стили (перенесены из дизайна один в один; в index.html встроены автоматически)
  assets/fonts/              шрифты (свои копии Google Fonts, без запросов к Google)
  assets/js/landing.js       логика лендинга: калькулятор, форма с подписью, FAQ, флип, звёзды…
  assets/js/transition.js    переход между страницами через лоадер
tools/
  pages.json                 тексты концепт-страниц
  build-pages.py             пересобирает концепт-страницы из pages.json
```

## Локальный просмотр

```
cd site && python3 -m http.server 8000
```

Откройте http://localhost:8000. Отправка формы локально выдаст ошибку: принимать заявки умеет только Netlify. Открыть `index.html` двойным кликом не получится: встроенным блокам нужен сервер.

## Публикация на Netlify

Настройки лежат в `netlify.toml`: публикуется папка `site/`, сборки нет.

**Вариант 1. Через GitHub (рекомендую): каждый пуш выкатывается сам.**
1. Запушьте репозиторий на GitHub.
2. В Netlify нажмите **Add new site → Import an existing project → GitHub** и выберите репозиторий. Поля сборки оставьте как есть: Netlify возьмёт их из `netlify.toml`.
3. Нажмите **Deploy**.

**Вариант 2. Вручную, без GitHub.** Откройте https://app.netlify.com/drop и перетащите туда папку `site/` или архив `tradequo-partners-site.zip`.

**Домен tradequopartners.com.** В Netlify откройте **Domain management → Add a domain** и добавьте `tradequopartners.com`. Дальше одно из двух:
- перенесите домен на DNS Netlify: у регистратора замените NS-серверы на те, что покажет Netlify;
- или оставьте DNS у регистратора и пропишите `A @ → 75.2.60.5` и `CNAME www → <имя-сайта>.netlify.app`.

HTTPS (Let's Encrypt) Netlify включит сам.

**Заявки с формы** уходят в Netlify Forms (форма `partner-request`). Они видны в разделе **Forms** панели Netlify. Там же можно включить уведомления на почту или в Slack: **Forms → Form notifications**. Если раздел Forms пустой, включите **Forms → Enable form detection** и передеплойте сайт.

## Что нужно решить до публичного запуска

- **Куда приходят заявки.** Сейчас форма отправляет их в Netlify Forms. Чтобы слать в CRM, поменяйте `data-endpoint="/"` у формы в `tools/i18n/landing.html` на адрес вебхука и пересоберите страницы (`python3 tools/build-i18n.py`). Поля уходят POST-запросом: `name`, `email`, `phone`.
- **Ссылки Privacy Policy и Partner Terms** пока ведут на `#`.
- **Концепт-страницы** закрыты от индексации (`noindex`), потому что тексты на них черновые. Кнопки на них, как и в дизайне, пока никуда не ведут. Когда тексты будут готовы, уберите строку `robots` в `tools/build-pages.py`, запустите `python3 tools/build-pages.py` и добавьте страницы в `site/sitemap.xml`.

## Правка концепт-страниц

Отредактируйте `tools/pages.json` и запустите `python3 tools/build-pages.py`.

## Новая версия ролика или 3D-блока из Claude Design

1. Положите новый HTML-файл в `site/embeds/` под тем же именем, например `tradequo-film.html`.
2. Запустите:
   ```
   cd tools && npm install && npm run optimize-embeds
   ```
   Скрипт переведёт файл на локальные three.js и React из `site/vendor/` и заранее скомпилирует JSX в `<имя>.app.js`. Без этого шага блок будет грузить Babel (~3 МБ) и компилировать код прямо в браузере, а страница начнёт тормозить.
3. Если в файле есть картинки, встроенные как `data:image/png;base64,…` (в ролике это `window.TQ_ASSETS`), пережмите их без потерь в WebP (Pillow: `save(..., 'WEBP', lossless=True, exact=True, method=6)`; пиксели остаются те же). Ролик рисует каждую картинку через `new Image()` и canvas, формат ему не важен. Так `tradequo-film.html` стал легче на треть (302 → 203 КБ в сжатом виде).
4. Если это ролик (`tradequo-film.html`): на главной он идёт видеофайлом, снятым с этого файла, поэтому перезапишите видео: `cd tools && node render-film.mjs` (несколько минут; см. «Ролик на главной — видео» ниже).
5. Запустите `python3 tools/stamp-assets.py`: он обновит метки версий `?v=…` в ссылках на файлы, чтобы браузеры не показывали старую версию из кэша.
6. Закоммитьте изменения: Netlify выкатит их сам.

### Когда грузятся 3D-блоки и ролик

Встроенные блоки (`iframe[data-embed]`) до первого действия посетителя (прокрутка, касание, клавиша) не грузятся вообще. После него:
- Infinite Flow (помечен `data-warm`) начинает грузиться сразу, в паузах между кадрами: запуск у него долгий, а заголовок «Infinite Flow» — часть самого встроенного блока, и при загрузке «на подходе» посетитель, который сразу листает вниз, ждал его на белом месте.
- Ролик — видео (см. ниже): после первого действия он только скачивается (это не нагружает страницу), играет, пока на экране.
- Остальные (кристаллы на главной, купол на /programs/; у обоих есть картинка-заглушка) запускаются примерно за полтора экрана до того, как до них долистают.
- Прыжок по оглавлению страницы или наверх пролетает блоки, не запуская их: запускаются те, что рядом с местом, где страница остановилась, остальные — когда к ним подойдут.
- Блок, скрытый через `display: none` (ролик на телефонах), не грузится никогда.

Код — `startEmbeds`, `holdEmbeds` и `startFilm` в `site/assets/js/landing.js`, пометки `data-warm` — в `tools/i18n/landing.html`.

### Ролик на главной — видео

Ролик TradeQuo Partner Program (24,2 с, по кругу) на главной — видеофайл (60 кадров/с, H.264: живой ролик двигался каждый кадр экрана, на 30 движение шло рывками) в `site/assets/film/`: `tradequo-film-1440.mp4` (2560×1440) там, где ролик занимает на экране больше ~1700 физических пикселей в ширину (ретина, масштаб 150%), и `tradequo-film-1080.mp4` (1920×1080, уменьшен из 1440 по Ланцошу) на остальных: браузер уменьшает видео простым способом, 1440 на экране в ~1240 точек рябил бы на тонких линиях, а 1080 на ретине растягивался бы и мылился; каждый посетитель качает один файл (выбор — в `startFilm`). Для браузеров без H.264 — `tradequo-film-1080.webm` (VP9). а не живая сцена. Живой ролик (`site/embeds/tradequo-film.html`: React, three.js и стеклянный логотип, который перерисовывается каждый кадр) был самым тяжёлым на странице, и на стыке с Infinite Flow (оба на экране) страница тормозила. Видео декодирует видеокарта — нагрузки почти нет. Видео снято с живого ролика кадр за кадром (`tools/render-film.mjs`), поэтому выглядит так же. Снято без плёночного зерна: зерно (движущийся шум по всему кадру) хуже всего поддаётся сжатию и съедает качество тёмных сцен (блоки на световых полосах, пропавшая сетка из точек). Его рисует страница поверх видео — та же текстура шума, что в ролике, сдвиг 24 раза в секунду, наложение overlay с силой 0,07, появляется на 1,7–2,2 с (`startFilm`, слой `.tq-film__grain` двигается через transform, без перерисовки). Сжатие подобрано под тёмный ролик (CRF 21, film-тюнинг x264, AQ с упором на тёмные места), цвета переводятся в BT.709, которым помечено видео (иначе красный уезжает). Поверх него — кнопки плеера ролика, как были: назад и вперёд на 1,5 с, пауза/воспроизведение (затемнены, пока курсор не над роликом и он не на паузе). Играет, пока на экране, вне экрана стоит; при «уменьшить движение» не запускается сам, стоит последняя сцена (23,5 с), пока не нажать воспроизведение. Разметка — `#film` в `tools/i18n/landing.html`, стили — раздел «the partner film» в `site.css`, код — `startFilm` в `landing.js`. Живой ролик остаётся в `site/embeds/` как исходник видео: поменяли его — перезапишите видео (`cd tools && node render-film.mjs`, потом `python3 tools/build-i18n.py`).

### Логотип возле FAQ — картинка

Стеклянный логотип TradeQuo в левой колонке FAQ на главной — статичный кадр, а не 3D-сцена: `site/assets/faq-logo.webp` (800×744, вдвое больше блока 400×372; прозрачный фон, 79 КБ). Кадр снят со сцены `site/embeds/tradequo-glass-logo.html` в покое, повёрнутой на −0,25 рад, чтобы были видны толщина и фаски, вместе с её фоном (светлые полосы, красное свечение у точки). На странице это обычный `<img>` с подписью `faq.frame`; three.js и WebGL ради него больше не грузятся. Сама сцена осталась в `site/embeds/`: чтобы вернуть её, поставьте вместо картинки прежний `<iframe data-embed data-src="{{root}}embeds/tradequo-glass-logo.html" …>` в `landing.html`. Чтобы переснять кадр: откройте сцену в окне 400×372 с масштабом 2 и «уменьшить движение», выставьте `tqGlassLogo.logo.rotation.y`, отрисуйте и сохраните скриншот с прозрачным фоном в WebP (quality 80, alpha_quality 100: при сжатии прозрачности мягкое свечение идёт полосами).

### Ролик на телефонах

На телефонах (до 640px) блока с роликом на главной нет: секция `#film` скрыта, её видео не грузится. Раньше там шло MP4 этого ролика (1,3 МБ — больше половины веса мобильной главной); его, скрипт и стили убрали (в истории git — коммит «Phones: partner film as an MP4…»). Десктоп и планшет показывают живой ролик `tradequo-film.html`. Ради экономии памяти подписи в 3D-кристаллах на телефоне рисуются в текстурах шириной 1024px вместо 2048 (`TX` в `embeds/crystals.html`).

После любой правки в `site/assets/` или `site/embeds/` тоже запускайте `python3 tools/stamp-assets.py`. Он проставит метки версий и заново встроит `site.css` (и `partner.css`) в страницы. `build-i18n.py` запускает его сам. Файлы в `assets/`, `embeds/` и `vendor/` браузеры кэшируют на год, поэтому без этого шага посетители могут не увидеть правку.

Что ещё делает `stamp-assets.py` ради скорости:
- встраивает CSS без комментариев (в исходных `site.css` и `partner.css` они остаются): страницы на 14–22% легче;
- встраивает в страницу только те правила, которые на ней могут сработать (`used_css` в `stamp-assets.py`): в `site.css` и `partner.css` лежат стили всех страниц, а правило остаётся, если все классы хотя бы одного его селектора есть на странице — в разметке (`class="…"`) или в скриптах, которые она загружает (встроенные и `assets/js/*.js`; скрипты добавляют классы на ходу, иногда собирая их из начала имени, это тоже учитывается). Классы внутри `:not()`, `:is()`, `:where()`, `:has()` не требуются; правила без классов, `@font-face`, `@keyframes`, `@property` остаются всегда. Внутренние страницы так стали вдвое легче (сжатая /programs/ — 25 КБ вместо 46). Править стили — как раньше, в `site.css` / `partner.css`: сборка сама разложит их по страницам. Если класс навешивается скриптом, которого страница не загружает (например, из встроя-iframe на родителя), впишите этот класс в разметку или в скрипт страницы, иначе его правило выпадет;
- ставит метку версии и на шрифты — в `url(…woff2)` во встроенном CSS, в шрифтах 3D-блоков и в `<link rel="preload">` (одна и та же метка, поэтому предзагрузка и `@font-face` — один запрос). Поэтому шрифт можно перезаписать под тем же именем (как делает `h1-fonts.py`): посетители получат новый, а не годовалую копию из кэша.

Встроенный CSS у всех страниц, включая 404 и концепт-страницы. Каждая страница заранее подгружает латиницу Inter, шрифт своего H1 и, где нужно, кириллицу/вьетнамский Inter или арабский/тайский шрифт (`h1_preload` и `font_css` в `build-i18n.py`) — заголовок не перескакивает, когда шрифт приходит.

## Шрифты: Inter + Syncopate

Шрифтовая пара всего сайта — **Inter + Syncopate**, других шрифтов на сайте нет:
- **Syncopate 700** — заголовки: H1 каждой страницы (главная, /programs/, /partner-terms/, /marketing-tools/, 404; класс `.tq-h1`, размер `clamp(22px, 3.1vw, 44px)`, на /programs/ свой, чтобы карточки помещались в первый экран) и заголовки разделов (H2; класс `.tq-h2`, размер `clamp(20px, 2.1vw, 30px)`), включая заголовок формы «Become a partner», «Request sent.», заголовок калькулятора и финальные призывы. Заглавными, с разрядкой 0,15em; слово шире экрана уменьшается (`data-fitw`). Подписи под роликом на /ib-tools/ — тоже `.tq-h2`, но с разрядкой из макета (0,03em). Старые классы заголовков (`.tp-h2`, `.tq-pc__title`, `.tp-final__title`, `.tp-tv__h`, `.tq-done__title`) задают только раскладку и цвет. Inter остаются названия программ в карточках /programs/ и маленькая надпись «Who it's for» над колодой — это не заголовки разделов. В Syncopate только латиница; для других языков похожие широкие шрифты (см. «Заголовок /programs/»), шрифт выбирается переменными `--h1f`/`--h2f` на `html:lang(…)`.
- **Inter** (вариативный, веса 300–700) — всё остальное: подзаголовки, текст, подписи полей, кнопки, печати и записка на экране успеха, бланк калькулятора, подписи и цифры в 3D-блоках (кристаллы, фильм, купол, бесконечная лента). Отдельно стоящие цифры — `tabular-nums` (на остальной текст не включено: у Inter от этого расширяется дефис). На телефонах текст не меньше 16px.
- Всё лежит на сайте (`site/assets/fonts/`), подключается с `font-display: swap`; к Google Fonts сайт и 3D-блоки не обращаются. Латиница Inter подгружается заранее, на украинском и вьетнамском — ещё кириллица/вьетнамский.
- Inter нет для арабского и тайского: эти буквы берутся из IBM Plex Sans Arabic и Noto Sans Thai, объявленных под именем `'Inter'` для своих диапазонов (`font_css` в `tools/build-i18n.py`, файлы в `site/assets/fonts/intl/`). CJK — системные шрифты, в подписях кристаллов — урезанные Noto (`TQ CJK`).
- Единственное исключение — список кодов стран в поле телефона: его рисует сама система, шрифт страницы на него не действует.

## Языки

На 18 языках собираются пять страниц: главная, «Partner Programs» (`/programs/`), «Partner Terms» с калькулятором (`/partner-terms/`; раньше страница была на `/commission-plan/`, и Netlify перенаправляет со старого адреса на новый с кодом 301 — правила в `netlify.toml`), «Marketing Tools» (`/marketing-tools/`; какое-то время страница называлась «Partner Tools» и жила на `/partner-tools/` — этот адрес оставлен для будущей страницы IB Tools для новичков в трейдинге, а пока временно, с кодом 302, ведёт на `/marketing-tools/`; правила в `netlify.toml`, их нужно удалить, когда новая страница будет готова) и «IB Tools» (`/ib-tools/`; пока шесть блоков, см. ниже). Английский лежит в корне сайта, остальные языки в папках `/ar/`, `/de/`, `/zh-hans/` и т. д. (например, `/de/programs/`). Переключатель языков находится в шапке. Концепт-страницы (`/dashboard/`, `/marketing-hub/`, `/academy/`, `/success-stories/`) убраны из меню; файлы остались на сайте, только на английском.

- `tools/i18n/landing.html`, `programs.html`, `commission.html` — шаблоны. Вместо текста в них ключи `{{ключ}}`, а в атрибутах `{{@ключ}}`. `{{> имя}}` вставляет общий кусок из `tools/i18n/partials/` (шапка, лоадер, веерное меню, футер), `{{faq:префикс:N}}` — N карточек FAQ. `{{lang}}` — язык для атрибута `lang` (`zh-Hans`), `{{code}}` — код языка в путях к файлам (`zh-hans`); кадры-заглушки кристаллов называются по `{{code}}`.
- `tools/i18n/strings/<язык>.json` — тексты главной и общих частей (меню, футер). Главный файл — `en.json`; если ключа нет в переводе, подставляется английский.
- `tools/i18n/strings/programs/<язык>.json`, `strings/commission/<язык>.json`, `strings/marketing/<язык>.json` и `strings/ibtools/<язык>.json` — тексты новых страниц.
- Список страниц — `PAGES` в начале `tools/build-i18n.py`; навигация по сайту в шапке — `NAV`, оглавление каждой страницы (веер справа внизу и красное меню на телефоне) — `TOC` там же.
- `tools/i18n/languages.json` — адреса, названия в переключателе, направление письма.
- `tools/i18n/TRANSLATION_BRIEF.md` — бриф для переводчиков: тон, глоссарий, ограничения длины.

Как поменять текст:
1. Исправьте `en.json` и переводы. Каждый язык — отдельный файл с теми же ключами.
2. Проверьте переводы: `python3 tools/check-strings.py` (ключи, метки `<red>`, цифры, длина надписей на кнопках).
3. Соберите страницы: `python3 tools/build-i18n.py`. Скрипт перезаписывает `site/[<язык>/][<страница>/]index.html`, поэтому правьте шаблоны и JSON, а не готовые страницы.
4. Если менялись подписи кристаллов (`embed.crys.*`), запустите `python3 tools/make-caption-fonts.py` (шрифты для CJK) и `cd tools && npm run posters` (кадры-заглушки).

### Навигация: шапка и оглавление страницы

**Шапка** — навигация по сайту: Home, Partner Programs, Partner Terms, Marketing Tools, IB Tools (подписи `fan.home`, `fan.programs`, `fan.commission`, `fan.marketing`, `fan.ibtools`; список `NAV` в `build-i18n.py`, вставляется на место `{{siteNav}}`). **Восьмой блок — «чёрная дыра»** (IB_Tools_Black_Hole, версия ноября 2026; раньше — IB_Tools_Black_Hole_Obsidian; `#flow`). - **Линза (только десктоп с мышью).** Пока на экране дыра и курсор над её диском, пространство вокруг курсора преломляется, как в гравитационной линзе: ближе к курсору картинка увеличивается и чуть закручивается, по краю — едва заметное цветное расслоение; дыра и кольца диска выгибаются к курсору. Это второй слой — WebGL поверх canvas: каждый кадр он берёт картинку canvas как текстуру и рисует её с искажением (шейдер `FS` в `ib-hole.js`; сила — `.42` закрутка и `.3` увеличение, радиус — `R × 1,2`, не меньше 120px). Линза плавно появляется и гаснет — когда курсор уходит с диска или сцена переходит к столбцам; пока её нет, слой выключен и не рисуется. Слой создаётся при первом движении мыши над блоком; на телефонах и планшетах (касание) его нет вовсе, без WebGL — тоже. Слой линзы собирается заранее, когда до блока два экрана, и тоже без блокировки (`KHR_parallel_shader_compile`), а не при первом движении мыши — иначе первое движение над диском подвисало на время компиляции шейдера.

### Форма заявки и экран успеха

На десктопе (от 900px) порядок в форме такой: имя, email, телефон, затем строка согласия с Privacy Policy и кнопка «Send request», под ними дата и три пункта (UP TO 87% OF SPREAD …). Так «Send request» помещается в первый экран от 1920×1080. На 1440×900 кнопка пока ниже края на ~90px. Порядок меняет только CSS (`order` в конце `site.css`), на телефоне форма идёт в порядке разметки.

Мобильное меню (красная кнопка справа внизу) пропускает нажатия сквозь себя, пока закрыто: нажимаются только сама кнопка и, когда меню открыто, его ссылки (`[data-fab] { pointer-events: none }` в `site.css`). Раньше закрытое меню невидимо перекрывало правую нижнюю половину экрана, и нажатия там пропадали. На всей странице стоит `touch-action: manipulation`: iOS не ждёт двойного тапа для зума, и быстрые повторные нажатия не теряются. В RTL (арабский) кнопка меню тоже стоит у правого края: колонка меню выравнивается по правому краю (`[dir="rtl"] [data-fab]` в `site.css`), раньше кнопка оказывалась примерно в 100px от края. Открытое меню закрывается нажатием в любое место вне его и клавишей Escape; после Escape фокус возвращается на кнопку (`startFab` в `landing.js`).

На телефонах (до 640px) у всего, что нажимают, зона нажатия не меньше 44px, как советуют Apple и Google. Мелкие элементы выглядят как раньше, но принимают нажатия чуть шире своих границ: Day/Month/Year на счёте, ссылка «See the commission plan», логотип. Кнопки языка и «Become a partner» в шапке — 44px. Точки под свайперами — кнопки 44×44 с маленькой точкой внутри. Исключение — ссылки Privacy/Terms внутри текста под формой: по правилам WCAG ссылкам внутри текста это не нужно. Мелкий текст на телефонах не меньше 11px для подписей капсом и моноширинных меток и не меньше 12px для обычного текста: мелкий шрифт в футере, метки на счёте, на карточках заработка и в отзывах. Правила собраны в конце `site.css` и в разделах счёта, калькулятора и карточек заработка (`partner.css`).

Код страны в поле телефона выбирается: поверх флага и кода лежит невидимый нативный список, поэтому на телефоне открывается системный выбор. В списке 243 страны, названия на языке страницы (их даёт браузер, `Intl.DisplayNames`), отсортированы по имени. По умолчанию ОАЭ (+971). Выбор уходит в заявке полем `phone_code`, например `DE +49`. Подсказка в поле номера подстраивается под страну: это пример мобильного номера этой страны в том виде, как его пишут после кода (для +971 — «50 123 4567», для +1 — «201 555 0123», для +49 — «1512 3456789»), тоже из `libphonenumber-js`. Телефонные коды взяты из `libphonenumber-js`, флаги — SVG из `flag-icons` (оба пакета под лицензией MIT, лицензия флагов лежит в `site/assets/flags/LICENSE`). Коды и примеры номеров — константа `DIAL` в `startDial` (`landing.js`, формат `ISO|код|пример;…`), флаги — `site/assets/flags/<код>.svg`, страница грузит только флаг выбранной страны.

Шрифт в полях формы — 16px. Меньше делать нельзя: Safari на iPhone и iPad увеличивает страницу, когда нажимаешь на поле с шрифтом меньше 16px.

Дата в форме подставляется сама: сегодняшняя, в формате ДД / ММ / ГГГГ. После нажатия «Send request» с кнопки улетает конверт, и форма отправляет поля на `data-endpoint`. Если сервер принял заявку, форма отъезжает назад и гаснет, а на её месте собирается экран успеха по макету Partner_Form_Success:
- заголовок «Request sent.»;
- конверт с сургучной печатью и почтовым штемпелем с сегодняшней датой;
- записка от руки «Thanks, {имя}! We’ll call you within 24 hours.»;
- три шага (Sent → Call → Start earning);
- кнопки «Partner Programs» и «Commission calculator».

Если сервер ответил ошибкой, экран успеха не показывается: под кнопкой появляется сообщение, и кнопку можно нажать снова.

- Разметка — `tools/i18n/partials/form-done.html`.
- Стили — раздел «Sign-up success screen» в `site.css`.
- Логика — `startForm` в `landing.js`.
- Тексты — ключи `done.*` в `strings/<язык>.json`. Заголовок берётся из `form.sent`, первая кнопка из `fan.programs`.

Обещание «позвоним в течение 2 минут» стоит в `done.call` и `done.s2d`. Если срок другой, поменяйте эти строки во всех языках. Между числом и единицей стоит неразрывный пробел, чтобы «2» не оставалась одна в конце строки. Другие «24 часа» на сайте (how.s2.d, reach.sub, pp.join.sub, FAQ) говорят о проверке заявки, а не о звонке, поэтому их не меняли.

Над заголовком формы больше нет логотипа TradeQuo, заголовок «Become a partner» стоит сразу под верхним краем формы.

### Стеклянные карточки

Везде, где раньше было «хромированное» стекло с металлической рамкой, теперь прозрачное «жидкое» стекло по макету Glass_Card_Grid_Liquid. Это:
- FAQ на главной;
- FAQ на остальных страницах;
- калькулятор и шаги на /partner-terms/;
- карточки на /marketing-tools/.

Устройство:
- **Стили** — раздел «Liquid glass» в конце `site.css`: класс `.tq-glass`. На партнёрских страницах это тот же стиль под старым именем `.tp-glass`.
- **Модификаторы:** `--panel` для больших панелей (без подъёма при наведении), `--flat` без фильтра фона, `--row` для строк FAQ.
- **Преломление** — SVG-фильтр `#tq-liquid`. Его добавляет в страницу `startGlass` в `landing.js` и включает классом `html.tq-liquid`, только в браузерах на Chromium (Chrome, Edge, Opera, Samsung Internet): Safari и Firefox не умеют SVG-фильтр в `backdrop-filter`, там стекло с обычным размытием.
- **Блик** следует за мышью, это тоже делает `startGlass`. На телефоне карточки просто стоят.

Лента отзывов на главной едет сама (один круг карточек за 64 секунды), но её можно тянуть мышью или свайпать пальцем в обе стороны, а на трекпаде — боковым свайпом двумя пальцами. После броска лента продолжает двигаться по инерции и плавно возвращается к обычной скорости. Когда на ленте мышь, лента стоит. Вертикальный свайп на телефоне прокручивает страницу. Это делает `startReviewsDrag` в `landing.js`. Без JS работает прежняя CSS-анимация; если в системе включено уменьшение движения, лента — обычная прокрутка.

Одно место оформлено иначе:
- **Отзывы на главной** — матовое стекло по макету Glass_Card_Grid (класс `.tq-frost`, раздел «Frosted glass» в самом конце `site.css`): молочный фон с зерном, при наведении радужная кромка и подъём. Размытия фона нет: лента движется каждый кадр и лежит на белом, размытие стоило бы кадров и не было бы видно.

### Заголовки и подзаголовки

Заголовки секций (h2), заголовки первого экрана (h1) и финальные заголовки на всех страницах, а также подзаголовки под ними увеличены в 1,6 раза. Заголовки внутри карточек, бланк формы, экран успеха и «Infinite Flow» не менялись.

На телефонах (до 640px) все подзаголовки 16px с межстрочным 1,45, как подзаголовок «Infinite Flow» (правило в `site.css`, раздел «Captions under headings»).

Подзаголовки под заголовками всегда в две строки. Это делает `startTwoLine` в `landing.js`:
- ширина подзаголовка ставится в rem, примерно в половину длины текста в одну строку, а `text-wrap: balance` выравнивает строки;
- если колонка уже́ этой половины (планшет, боковая колонка FAQ), шрифт подзаголовка уменьшается ровно настолько, чтобы влезли две строки, но не меньше 65% и не меньше 15px;
- если и так не влезает (длинные подзаголовки на телефонах, абзац у купола на /programs/), размер не трогается, и текст занимает больше строк;
- подзаголовок с ручным переносом (`<brd/>`, как у калькулятора) на десктопе делится по нему, а на планшете и телефоне — пополам.

Что считается подзаголовком: абзацы с `data-sub2` на главной и классы `.tp-sub`, `.tp-final__sub`, `.tp-dome-copy__sub` на партнёрских страницах. Подзаголовок в «Infinite Flow» делит пополам свой скрипт внутри `embeds/infinite-flow.html`.

Для этого отступы зависят от высоты окна, а в невысоком окне (до 820px) заголовок чуть меньше и «сцена» карточек ниже. Примечание на телефоне стоит под кнопками, поэтому обе кнопки видны в первом экране (390×737: английский и большинство языков; в немецком, испанском, японском, тайском и вьетнамском вторая кнопка ниже края на 6–42px).

Кнопки первого экрана — по макетам: пилюля с круглой кнопкой-стрелкой в начале. У «Discuss your terms» чёрный фон и красный круг с белой стрелкой, у «Become a partner» красный фон и белый круг с красной стрелкой; снизу «бортик» и тень. При наведении стрелка сдвигается вперёд. Под ними по центру примечание о ставках, а под примечанием две кнопки: чёрная «Discuss your terms» и красная «Become a partner» (`nav.cta`, как в шапке). Обе ведут на форму заявки главной. Калькулятор стоит сразу под этим экраном.

Карточки:

| Профиль | Трейдеры | Лотов на трейдера в месяц | В месяц | В день | В год |
|---|---|---|---|---|---|
| Content creator | 23 | 12 | $2,070 | $69 | $24,840 |
| Trading community | 140 | 18 | $18,900 | $630 | $226,800 |
| Education business | 460 | 27 | $93,150 | $3,105 | $1,117,800 |

Считается так же, как в калькуляторе: трейдеры × лоты × $7.50; день — тридцатая часть месяца, год — двенадцать месяцев. Суммы записаны в разметке (`tools/i18n/commission.html`) и не пересчитываются.

Как ведут себя карточки:
- под мышью наклоняются за курсором, по ним скользит блик;
- клик, Enter или пробел выбирает карточку: красная рамка, метка «Selected», остальные две бледнеют; повторный клик снимает выбор;
- свечи на задней карточке рисует скрипт, это украшение.

Уже 1040px три карточки в ряд не помещаются, и ряд становится свайпером:
- лента идёт от края до края экрана, после свайпа карточка встаёт по центру;
- соседние карточки чуть меньше и бледнее и уменьшаются к центральной, их края видны по бокам;
- под лентой три точки, тап по точке листает к своей карточке;
- тап по боковой карточке выдвигает её в центр, тап по центральной выбирает её;
- если пролистать к другой карточке, выбор снимается.

Ширина карточки в свайпере — `--cw` в `partner.css` (78% экрана, от 280 до 380px). Масштаб и прозрачность боковых карточек считает `plan.js` по ходу прокрутки.

Стили — раздел «commission page hero» в конце `partner.css`, поведение — в `plan.js`. Тексты — ключи `cp.earn.*` в `strings/commission/<язык>.json`.

### Калькулятор комиссий

Калькулятор один и тот же на главной и на /partner-terms/, по макету Payout_Calculator_Receipt_Dark. Это тёмная панель:
- сверху заголовок и подпись страницы (главная — `calc.title`/`calc.sub`, /partner-terms/ — `cp.hero.h1`/`cp.hero.sub`);
- слева стеклянный «терминал»: два слайдера на шкале с делениями (лоты на трейдера 10–1000, активные трейдеры 1–300), переключатель Day / Month / Year и кнопка «Become a partner» на форму;
- справа чек PAYOUT, который «печатается» из серебристой щели: номер, дата, период, строка «Rebate on client volume», бесплатные комиссии, итог с подписью «TOTAL PAYOUT / MONTH» (`inv.totDay`/`inv.totMonth`/`inv.totYear`), штрихкод и штамп PAID.

Разметка — `tools/i18n/partials/calc-open.html` и `calc-body.html`: страница ставит свой заголовок между ними. Стили — раздел «Payout calculator» в конце `site.css`, логика — `startCalculator` в `landing.js`. Слайдеры — обычные `input type=range` (работают с клавиатуры) под нарисованной шкалой. Под панелью примечание `calc.note`.

На планшете и телефоне (до 900px) одна колонка: чек над терминалом, чтобы итог было видно, пока двигаешь слайдеры. Чтобы чек и терминал помещались на один экран, чек там заканчивается на итоге (штрихкода и штампа PAID нет), в терминале нет строки «Terminal · TQ-…», а подпись слайдера и его число стоят в одной строке над шкалой. На телефоне (до 640px) всё ещё плотнее: пара занимает около 620–650px по высоте и целиком видна на экране 390×664. Длинные числа и длинное слово вместо PAYOUT (например, AUSZAHLUNG) уменьшаются, чтобы влезть в чек.

Расчёт: лоты на трейдера × активные трейдеры × одна ставка за лот, $7.50. Ставка задана константой `RATE` в `startCalculator`, а число «$7.50» в тексте — в строке `inv.rebateCalc`. Если ставка меняется, правьте оба места, а заодно примеры заработка на /partner-terms/ (суммы в карточках и `cp.earn.note`).

`site/assets/js/plan.js` на /partner-terms/ ведёт карточки примеров на первом экране.

### Блок «Paid every day. No fees.» на /partner-terms/

По макету Paid_Daily_Silver: светлая серебристая панель с белым свечением сверху и тонкими вертикальными линиями внизу. Конкретное время расчёта в блоке не пишем, только «каждый день» (подзаголовок `cp.pay.sub`, третий шаг «Settled daily» с номером 03). Четыре шага выплаты (`cp.pay.t1…4` / `d1…4`) стоят в ряд на бледно-красной линии. Раз в 1,9 секунды подсвечивается следующий шаг: красная линия с бегущим бликом дотягивается до него (в макете линия серебряная, по просьбе сделана красной), его шарик раздувается в полированную серебряную сферу, иконка краснеет и коротко анимируется (свечи, стрелка, стрелка часов, кошелёк), а над шариком всплывает подсказка: «+1 trade», «+$7.50», «Settled», «$0 fees» (ключи `cp.pay.c1`, `c3`, `c4`; «+$7.50» — та же ставка, что в калькуляторе). На планшете шаги 2×2 без линии, на телефоне — по одному, шарик слева от текста.

Оба пошаговых блока (этот и «How to get them» на Partner Tools) ведёт одна функция `startSteppers` в `landing.js`: разметка `[data-stepper]` с шагами `[data-step]`, интервал в `data-every`. Она работает, только пока блок на экране, и каждый раз начинает с первого шага; при «уменьшить движение» сразу показывает последний шаг без анимации. Анимации — классы и прозрачность слоёв, без перерисовки размытия: у шариков нет backdrop-filter.

Чек считает за день, месяц или год: переключатель Day / Month / Year в терминале (`[data-inv-per]`, подписи `inv.pDay`/`inv.pMonth`/`inv.pYear`). От выбора зависят сумма, строка «Rebate on client volume», число лотов, поле PERIOD и подпись над итогом. День — тридцатая часть месяца, год — двенадцать месяцев (`PER` в `startCalculator`).
