# TradeQuo Partner Program: сайт

Статический сайт без сборки. Всё, что уходит на хостинг, лежит в `site/`.

```
site/
  index.html                 лендинг (Partner Program v2)
  commission-plans/ dashboard/ marketing-hub/ academy/ success-stories/
                             концепт-страницы, у каждой свой URL
  embeds/                    3D-блоки и ролики (iframe, грузятся при подходе к экрану)
  vendor/                    three.js и React — свои копии, без внешних CDN
  assets/css/site.css        стили (перенесены из дизайна один в один; в index.html встроены автоматически)
  assets/fonts/              шрифты (свои копии Google Fonts, без запросов к Google)
  assets/js/landing.js       логика лендинга: калькулятор, форма с подписью, FAQ, флип, звёзды…
  assets/js/transition.js    переход между страницами через лоадер
tools/
  pages.json                 тексты концепт-страниц
  build-pages.py             пересобирает концепт-страницы из pages.json
```

## Локальный просмотр

```
cd site && python3 -m http.server 8000
```

Откройте http://localhost:8000. Отправка формы локально выдаст ошибку: принимать заявки умеет только Netlify. Открыть `index.html` двойным кликом не получится: встроенным блокам нужен сервер.

## Публикация на Netlify

Настройки лежат в `netlify.toml`: публикуется папка `site/`, сборки нет.

**Вариант 1. Через GitHub (рекомендую): каждый пуш выкатывается сам.**
1. Запушьте репозиторий на GitHub.
2. В Netlify нажмите **Add new site → Import an existing project → GitHub** и выберите репозиторий. Поля сборки оставьте как есть: Netlify возьмёт их из `netlify.toml`.
3. Нажмите **Deploy**.

**Вариант 2. Вручную, без GitHub.** Откройте https://app.netlify.com/drop и перетащите туда папку `site/` или архив `tradequo-partners-site.zip`.

**Домен tradequopartners.com.** В Netlify откройте **Domain management → Add a domain** и добавьте `tradequopartners.com`. Дальше одно из двух:
- перенесите домен на DNS Netlify: у регистратора замените NS-серверы на те, что покажет Netlify;
- или оставьте DNS у регистратора и пропишите `A @ → 75.2.60.5` и `CNAME www → <имя-сайта>.netlify.app`.

HTTPS (Let's Encrypt) Netlify включит сам.

**Заявки с формы** уходят в Netlify Forms (форма `partner-request`). Они видны в разделе **Forms** панели Netlify. Там же можно включить уведомления на почту или в Slack: **Forms → Form notifications**. Если раздел Forms пустой, включите **Forms → Enable form detection** и передеплойте сайт.

## Что нужно решить до публичного запуска

- **Куда приходят заявки.** Сейчас форма отправляет их в Netlify Forms. Чтобы слать в CRM, поменяйте `data-endpoint="/"` у формы в `tools/i18n/landing.html` на адрес вебхука и пересоберите страницы (`python3 tools/build-i18n.py`). Поля уходят POST-запросом: `name`, `email`, `phone`.
- **Ссылки Privacy Policy и Partner Terms** пока ведут на `#`.
- **Концепт-страницы** закрыты от индексации (`noindex`), потому что тексты на них черновые. Кнопки на них, как и в дизайне, пока никуда не ведут. Когда тексты будут готовы, уберите строку `robots` в `tools/build-pages.py`, запустите `python3 tools/build-pages.py` и добавьте страницы в `site/sitemap.xml`.

## Правка концепт-страниц

Отредактируйте `tools/pages.json` и запустите `python3 tools/build-pages.py`.

## Новая версия ролика или 3D-блока из Claude Design

1. Положите новый HTML-файл в `site/embeds/` под тем же именем, например `tradequo-film.html`.
2. Запустите:
   ```
   cd tools && npm install && npm run optimize-embeds
   ```
   Скрипт переведёт файл на локальные three.js и React из `site/vendor/` и заранее скомпилирует JSX в `<имя>.app.js`. Без этого шага блок будет грузить Babel (~3 МБ) и компилировать код прямо в браузере, а страница начнёт тормозить.
3. Запустите `python3 tools/stamp-assets.py`: он обновит метки версий `?v=…` в ссылках на файлы, чтобы браузеры не показывали старую версию из кэша.
4. Закоммитьте изменения: Netlify выкатит их сам.

### Ролик на телефонах

На телефонах (до 640px) блока с роликом на главной нет: секция `#film` скрыта, её iframe не грузится. Раньше там шло MP4 этого ролика (1,3 МБ — больше половины веса мобильной главной); его, скрипт и стили убрали (в истории git — коммит «Phones: partner film as an MP4…»). Десктоп и планшет показывают живой ролик `tradequo-film.html`. Ради экономии памяти подписи в 3D-кристаллах на телефоне рисуются в текстурах шириной 1024px вместо 2048 (`TX` в `embeds/crystals.html`).

После любой правки в `site/assets/` или `site/embeds/` тоже запускайте `python3 tools/stamp-assets.py`. Он проставит метки версий и заново встроит `site.css` в `index.html`. `build-pages.py` делает это сам. Файлы в `assets/`, `embeds/` и `vendor/` браузеры кэшируют на год, поэтому без этого шага посетители могут не увидеть правку.

## Языки

На 18 языках собираются четыре страницы: главная, «Partner Programs» (`/programs/`), «Commission Plan» с калькулятором (`/partner-terms/`; раньше страница была на `/commission-plan/`, и Netlify перенаправляет со старого адреса на новый с кодом 301 — правила в `netlify.toml`) и «Marketing Tools» (`/marketing-tools/`). Английский лежит в корне сайта, остальные языки в папках `/ar/`, `/de/`, `/zh-hans/` и т. д. (например, `/de/programs/`). Переключатель языков находится в шапке. Новые страницы открываются только из веерного меню справа внизу (на телефоне — из красной кнопки меню). Концепт-страницы (`/dashboard/`, `/marketing-hub/`, `/academy/`, `/success-stories/`) убраны из меню; файлы остались на сайте, только на английском.

- `tools/i18n/landing.html`, `programs.html`, `commission.html` — шаблоны. Вместо текста в них ключи `{{ключ}}`, а в атрибутах `{{@ключ}}`. `{{> имя}}` вставляет общий кусок из `tools/i18n/partials/` (шапка, лоадер, веерное меню, футер), `{{faq:префикс:N}}` — N карточек FAQ. `{{lang}}` — язык для атрибута `lang` (`zh-Hans`), `{{code}}` — код языка в путях к файлам (`zh-hans`); кадры-заглушки кристаллов называются по `{{code}}`.
- `tools/i18n/strings/<язык>.json` — тексты главной и общих частей (меню, футер). Главный файл — `en.json`; если ключа нет в переводе, подставляется английский.
- `tools/i18n/strings/programs/<язык>.json`, `strings/commission/<язык>.json` и `strings/marketing/<язык>.json` — тексты новых страниц.
- Список страниц и пунктов веерного меню — `PAGES` и `FAN` в начале `tools/build-i18n.py`.
- `tools/i18n/languages.json` — адреса, названия в переключателе, направление письма.
- `tools/i18n/TRANSLATION_BRIEF.md` — бриф для переводчиков: тон, глоссарий, ограничения длины.

Как поменять текст:
1. Исправьте `en.json` и переводы. Каждый язык — отдельный файл с теми же ключами.
2. Проверьте переводы: `python3 tools/check-strings.py` (ключи, метки `<red>`, цифры, длина надписей на кнопках).
3. Соберите страницы: `python3 tools/build-i18n.py`. Скрипт перезаписывает `site/[<язык>/][<страница>/]index.html`, поэтому правьте шаблоны и JSON, а не готовые страницы.
4. Если менялись подписи кристаллов (`embed.crys.*`), запустите `python3 tools/make-caption-fonts.py` (шрифты для CJK) и `cd tools && npm run posters` (кадры-заглушки).

### Блок «How it works» (три шага до первой выплаты)

Один и тот же блок стоит на всех трёх страницах. На лендинге он идёт после цифр, на /programs/ — после серой подложки перед «Join 30,000+ partners», на /partner-terms/ — перед FAQ. Разметка — `tools/i18n/partials/how.html`, тексты — ключи `how.*` в `strings/<язык>.json`, анимацию линии ведёт `startHowLine` в `landing.js`. Кнопка на лендинге прокручивает к форме, а с других страниц ведёт на форму лендинга с анимацией перехода (`signupHref`/`signupNav` в `build-i18n.py`).

### Карточки программ на /programs/

Три карточки (Introducing Broker, Partner Network, White Label) по макету Partner_Cards 5a. Карточки тёмные, в верхнем углу (со стороны предмета) красная подсветка. Серой подложки под карточками нет: они стоят прямо на странице.

Что в карточке:
- номер, название программы, красная строка (`pp.pX.title`) и серебряный предмет программы;
- под тонкой линией надпись (`pp.pX.eyebrow`), крупная красная цифра (`pp.pX.big`) и подпись (`pp.pX.sub`);
- три пункта, кнопки «Become a partner» и «Commission plan» (у третьей — «Partner perks»), строка «For educators, …» (`pp.pX.for`).

Тексты лежат в `strings/programs/<язык>.json`, стили — раздел «Program cards» в `partner.css`.

Предметы — статичные картинки `site/assets/programs/{link,network,temple}.webp` (прозрачный фон, 2x). Они сняты из макета в его же неподвижных позах: цепь и сеть — сцены TQProgram3D в серебре, храм — MTArt в тёмной теме. Живого 3D в карточках нет.

Подгонка текста (`startFitWide` в `landing.js`):
- название переносится раньше, чем дойдёт до предмета (ширина своя у каждой карточки, от `--nf`);
- слово шире этого и крупная цифра, не влезающая в карточку, уменьшаются, пока не влезут (`data-fitw`);
- ссылка рядом с кнопкой стоит в одну строку с ней во всех трёх карточках или, если хоть в одной не помещается, под кнопкой во всех трёх (класс `is-stack`), чтобы кнопки стояли на одной высоте;
- в японском и китайском названия переносятся только там, где в строке стоит пробел нулевой ширины.

Кнопки карточек видны в первом экране во всех языках: на десктопе 1440×900, 1600×900, 1920×1080, 1280×800, 1536×864, 1440×790 и 1536×730, на телефоне 390×737 и 430×800. Ради этого строка «For educators, …» стоит под кнопками, а на невысоких экранах (до 940 и до 800px) карточка и заголовок ужимаются. Подзаголовок страницы на десктопе (от 961px, карточки в ряд) стоит под карточками (`.tp-hero__after`). На телефоне и планшете он остаётся над карточками; на телефоне короткий (`pp.hero.subShort`; видимый вариант выбирают классы `.tq-ph` / `.tq-nph` в `site.css`).

На телефонах (до 640px) три карточки программ (Introducing Broker, Partner Network, White Label) стоят в ряд и листаются вбок свайпом. Карточка занимает 86% ширины, край соседней виден, после свайпа карточка встаёт по центру. Под карточками три точки: активная красная, тап по точке листает к своей карточке. Это обычная прокрутка браузера с доводкой (CSS scroll-snap в `partner.css`); `startProgSwiper` в `landing.js` только переключает точки и листает по тапу. Подписи точек для экранных дикторов — названия программ (`pp.p1.title`…`pp.p3.title`). Начиная с 641px карточки стоят как раньше: в столбик на планшете, в ряд на десктопе.

### Блок «Who it's for → Why partners choose TradeQuo» на /programs/

Одна сцена на прокрутке по макету TradeQuo_Partner_Flow, сразу после карточек программ:
- **Сначала блок «Built for people who move traders».** Пять вкладок с типами партнёров, текст выбранного и метка «Best fit» с подходящей программой. Ниже 3D-платформа с эмблемой выбранного типа, стрелки и кнопка «Apply as a partner». Вкладки, стрелки и клик по платформе переключают тип, а сама платформа листает типы по кругу.
- **Дальше на прокрутке.** Блок закрепляется на экране, фон и текст уходят, платформа поднимается и встаёт. Её снимок разворачивается во весь экран и становится тёмным блоком «Why partners choose TradeQuo», где раздаются веером шесть карточек-перков и кнопка-пазл «Start earning».
- **Длина и этапы прокрутки — как у перехода Infinite Flow → перки на главной** (`startFlip`): трек 326vh, то есть 226vh прокрутки (на главной 340vh: здесь перки появляются примерно на один шаг колёсика раньше), и та же плавная «догонялка». Если весь путь принять за 1: текст типов гаснет к 0,17, платформа встаёт к 0,52, затем растёт на весь экран (0,56–0,86) и темнеет, заголовок перков появляется на 0,76–0,94, кнопка и раздача карточек — с 0,82. Этапы описаны в комментарии к `startWhoFlow` в `landing.js`; если меняется переход на главной, поправьте и их.
- **Ссылка «Benefits» в шапке** ведёт к раскрытому вееру.
- **Отличия от макета.** Веер карточек стоит на 72px выше (но не ближе ~6,5% высоты экрана к заголовку — `startWhoFlow`, переменная `B`), кнопка-пазл — на 25px выше. После сцены тёмный блок не обрывается: красное свечение продолжается, и цвет плавно уходит в белый, с которого начинается следующая секция (`#pf-tail`).
- **Телефоны (до 900px) и уменьшенное движение:** ничего не закрепляется, блоки идут друг за другом. Перки устроены как Partner perks на главной, но без бейджа и подписи: заголовок по центру, карточки сеткой (на телефоне 2 в ряд и пониже, около 214px; на планшете 3), кнопка «Start earning» в конце.
- **Телефоны (до 640px), типы партнёров:** вместо пяти строк и отдельной истории — свайпер карточек. На каждой карточке номер, тип, его история и «Best fit». 3D-платформа и карточки собраны в одну белую плашку: сверху платформа с предметом и стрелками (44px), под ней текст типа, который при свайпе сдвигается внутри плашки. Под плашкой точки, ниже кнопка. Карточка в центре выбирает тип на 3D-платформе, а стрелки и тап по платформе листают карточки. Сама по себе платформа на телефоне типы не перебирает, чтобы карточки не уезжали во время чтения (`hold` в `partner-flow.js`).

Где что лежит:
- разметка — `tools/i18n/programs.html` (всё с префиксом `pf-`);
- стили — раздел «Who it's for → Why partners choose» в конце `partner.css`;
- прокрутка, вкладки и раздача — `startWhoFlow` в `landing.js`;
- 3D-платформа — `site/assets/js/partner-flow.js`, её грузит страница, когда сцена уже близко. three.js берётся из `site/vendor`. Без WebGL вместо платформы тёмная плашка, остальное работает.

Тексты: вкладки и истории — `pp.who.*`, заголовок перков — `pp.ben.title`, карточки и подписи — `pp.perks.*`. Посадочный талон на шестой карточке (BOARDING PASS, YOU → ANY) — декоративный и не переводится.

### Блок «A broker traders trust» на /programs/

Когда блок в одну колонку (до 1100px), порядок такой: заголовок и подпись, купол, цифры, потом кнопки «Join 30K+ partners» и «Read the reviews». На телефоне всё по центру.

Купол из шестиугольников вокруг точки TradeQuo (`site/embeds/trust-dome.html`, по макету Trust_Dome_Partners). Четыре цифры — обычный текст страницы рядом со сценой (`[data-stat]` в `programs.html`, подписи `embed.crys.*`). Пока цифры стоят по углам сцены, сцена проявляет их по очереди и рисует к ним линии от ячеек купола. На телефоне они стоят сеткой под сценой, и сцена их не трогает. Подписи рисков, которые отскакивают от купола, — `embed.dome.r1`…`r4` в `strings/<язык>.json`. Сцена стоит на первом кадре (плоское поле, как кадр-заглушка `site/assets/posters/trust-dome.webp`) и проигрывает сборку купола с начала, когда на экране оказывается половина сцены. Цифры проявляются по мере того, как загораются их ячейки; если цифры уже были на экране, когда сцена загрузилась, они остаются видны. Клик по сцене проигрывает сборку заново. Текст у купола — 22px (на телефоне 16px), сцена не шире 540px, отступы панели 48px сверху и снизу. Кадр-заглушка: `cd tools && node render-program-posters.mjs trust`.

### Страница Marketing Tools (`/marketing-tools/`)

Собрана в стиле остальных партнёрских страниц, шаблон — `tools/i18n/marketing.html`:
- hero по макету TradeQuo_Marketing_Tools_Hero (подробнее ниже): тёмный экран во всю ширину с четырьмя инструментами в 3D, заголовок «Marketing tools.» и кнопка «Become a partner» внизу;
- каталог промо-материалов (`#library`) по макету Marketing_Materials_Bento_Glass: серая панель с тонкими красными, чёрными и стальными линиями, поверх неё бенто из стеклянных плиток. Шесть форматов — баннеры, лендинги, видео, GIF, посты для соцсетей, логотипы и брендбук (`mt.lib.N.t`/`.d`); у каждого номер и макет формата из HTML (`.tp-bm`, надписи в макетах — ключи `mt.mock.*`). Седьмая тёмная плитка «Need something specific?» со ссылкой «Ask your manager» ведёт на форму заявки (`mt.lib.custom.*`). На десктопе сетка 4×3 как в макете, на планшете и телефоне — две колонки, большие плитки на всю ширину. В арабском макеты стоят зеркально, сами рисунки не отражаются. Стили — раздел «Marketing Tools: promo materials» в конце `partner.css`;
- «How to get them» (`#get`): четыре шага от Client Portal до аудитории. Первый шаг берёт тексты `how.s2.*` из блока How it works, остальные — `mt.get.2…4.*`. Шаги намеренно короткие и общие: когда будут известны детали (название раздела в портале, выбор языка и размера, код для вставки), поправьте `mt.get.*`;
- «Data and people on your side» (`#support`) по макету Data_and_People_Section: две светло-серые карточки, у каждой сверху иллюстрация, под ней шестиугольная иконка, заголовок и текст (`mt.track.*`, `mt.mgr.*`). Слева — наклонённая в 3D панель партнёра: три показателя (регистрации, лоты, заработок) и столбики, которые обновляются раз в 1,6 секунды, пока блок на экране (`startLiveDash` в `landing.js`; при «уменьшить движение» панель неподвижна). ### Форма заявки и экран успеха

На десктопе (от 900px) порядок в форме такой: имя, email, телефон, затем строка согласия с Privacy Policy и кнопка «Send request», под ними дата и три пункта (UP TO 87% OF SPREAD …). Так «Send request» помещается в первый экран от 1920×1080. На 1440×900 кнопка пока ниже края на ~90px. Порядок меняет только CSS (`order` в конце `site.css`), на телефоне форма идёт в порядке разметки.

Мобильное меню (красная кнопка справа внизу) пропускает нажатия сквозь себя, пока закрыто: нажимаются только сама кнопка и, когда меню открыто, его ссылки (`[data-fab] { pointer-events: none }` в `site.css`). Раньше закрытое меню невидимо перекрывало правую нижнюю половину экрана, и нажатия там пропадали. На всей странице стоит `touch-action: manipulation`: iOS не ждёт двойного тапа для зума, и быстрые повторные нажатия не теряются. В RTL (арабский) кнопка меню тоже стоит у правого края: колонка меню выравнивается по правому краю (`[dir="rtl"] [data-fab]` в `site.css`), раньше кнопка оказывалась примерно в 100px от края. Открытое меню закрывается нажатием в любое место вне его и клавишей Escape; после Escape фокус возвращается на кнопку (`startFab` в `landing.js`).

На телефонах (до 640px) у всего, что нажимают, зона нажатия не меньше 44px, как советуют Apple и Google. Мелкие элементы выглядят как раньше, но принимают нажатия чуть шире своих границ: Day/Month/Year на счёте, ссылка «See the commission plan», логотип. Кнопки языка и «Become a partner» в шапке — 44px. Точки под свайперами — кнопки 44×44 с маленькой точкой внутри. Исключение — ссылки Privacy/Terms внутри текста под формой: по правилам WCAG ссылкам внутри текста это не нужно. Мелкий текст на телефонах не меньше 11px для подписей капсом и моноширинных меток и не меньше 12px для обычного текста: мелкий шрифт в футере, метки на счёте, на карточках заработка и в отзывах. Правила собраны в конце `site.css` и в разделах счёта, калькулятора и карточек заработка (`partner.css`).

Код страны в поле телефона выбирается: поверх флага и кода лежит невидимый нативный список, поэтому на телефоне открывается системный выбор. В списке 243 страны, названия на языке страницы (их даёт браузер, `Intl.DisplayNames`), отсортированы по имени. По умолчанию ОАЭ (+971). Выбор уходит в заявке полем `phone_code`, например `DE +49`. Подсказка в поле номера подстраивается под страну: это пример мобильного номера этой страны в том виде, как его пишут после кода (для +971 — «50 123 4567», для +1 — «201 555 0123», для +49 — «1512 3456789»), тоже из `libphonenumber-js`. Телефонные коды взяты из `libphonenumber-js`, флаги — SVG из `flag-icons` (оба пакета под лицензией MIT, лицензия флагов лежит в `site/assets/flags/LICENSE`). Коды и примеры номеров — константа `DIAL` в `startDial` (`landing.js`, формат `ISO|код|пример;…`), флаги — `site/assets/flags/<код>.svg`, страница грузит только флаг выбранной страны.

Шрифт в полях формы — 16px. Меньше делать нельзя: Safari на iPhone и iPad увеличивает страницу, когда нажимаешь на поле с шрифтом меньше 16px.

Дата в форме подставляется сама: сегодняшняя, в формате ДД / ММ / ГГГГ. После нажатия «Send request» с кнопки улетает конверт, и форма отправляет поля на `data-endpoint`. Если сервер принял заявку, форма отъезжает назад и гаснет, а на её месте собирается экран успеха по макету Partner_Form_Success:
- заголовок «Request sent.»;
- конверт с сургучной печатью и почтовым штемпелем с сегодняшней датой;
- записка от руки «Thanks, {имя}! We’ll call you within 24 hours.»;
- три шага (Sent → Call → Start earning);
- кнопки «Partner Programs» и «Commission calculator».

Если сервер ответил ошибкой, экран успеха не показывается: под кнопкой появляется сообщение, и кнопку можно нажать снова.

- Разметка — `tools/i18n/partials/form-done.html`.
- Стили — раздел «Sign-up success screen» в `site.css`.
- Логика — `startForm` в `landing.js`.
- Тексты — ключи `done.*` в `strings/<язык>.json`. Заголовок берётся из `form.sent`, первая кнопка из `fan.programs`.

Обещание «позвоним в течение 24 часов» стоит в `done.call` и `done.s2d`. Если срок другой, поменяйте эти строки во всех языках.

Посмотреть экран успеха, ничего не отправляя: откройте главную с `?preview=sent` (например, `/de/?preview=sent`), заполните email и нажмите кнопку.

### Стеклянные карточки

Везде, где раньше было «хромированное» стекло с металлической рамкой, теперь прозрачное «жидкое» стекло по макету Glass_Card_Grid_Liquid. Это:
- FAQ на главной;
- FAQ на остальных страницах;
- калькулятор и шаги на /partner-terms/;
- карточки на /marketing-tools/.

Устройство:
- **Стили** — раздел «Liquid glass» в конце `site.css`: класс `.tq-glass`. На партнёрских страницах это тот же стиль под старым именем `.tp-glass`.
- **Модификаторы:** `--panel` для больших панелей (без подъёма при наведении), `--flat` без фильтра фона, `--row` для строк FAQ.
- **Преломление** — SVG-фильтр `#tq-liquid`. Его добавляет в страницу `startGlass` в `landing.js` и включает классом `html.tq-liquid`, только в браузерах на Chromium (Chrome, Edge, Opera, Samsung Internet): Safari и Firefox не умеют SVG-фильтр в `backdrop-filter`, там стекло с обычным размытием.
- **Блик** следует за мышью, это тоже делает `startGlass`. На телефоне карточки просто стоят.

Лента отзывов на главной едет сама (один круг карточек за 64 секунды), но её можно тянуть мышью или свайпать пальцем в обе стороны, а на трекпаде — боковым свайпом двумя пальцами. После броска лента продолжает двигаться по инерции и плавно возвращается к обычной скорости. Когда на ленте мышь, лента стоит. Вертикальный свайп на телефоне прокручивает страницу. Это делает `startReviewsDrag` в `landing.js`. Без JS работает прежняя CSS-анимация; если в системе включено уменьшение движения, лента — обычная прокрутка.

Одно место оформлено иначе:
- **Отзывы на главной** — матовое стекло по макету Glass_Card_Grid (класс `.tq-frost`, раздел «Frosted glass» в самом конце `site.css`): молочный фон с зерном, при наведении радужная кромка и подъём. Размытия фона нет: лента движется каждый кадр и лежит на белом, размытие стоило бы кадров и не было бы видно.

Каталог материалов на /marketing-tools/ — стеклянные плитки (размытие 26px) на серой панели с линиями из макета: линии просвечивают сквозь стекло.

### Заголовки и подзаголовки

Заголовки секций (h2), заголовки первого экрана (h1) и финальные заголовки на всех страницах, а также подзаголовки под ними увеличены в 1,6 раза. Заголовки внутри карточек, бланк формы, экран успеха и «Infinite Flow» не менялись.

Подзаголовки под заголовками всегда в две строки. Это делает `startTwoLine` в `landing.js`:
- ширина подзаголовка ставится в rem, примерно в половину длины текста в одну строку, а `text-wrap: balance` выравнивает строки;
- если колонка уже́ этой половины (планшет, боковая колонка FAQ), шрифт подзаголовка уменьшается ровно настолько, чтобы влезли две строки, но не меньше 65% и не меньше 15px;
- если и так не влезает (длинные подзаголовки на телефонах, абзац у купола на /programs/), размер не трогается, и текст занимает больше строк;
- подзаголовок с ручным переносом (`<brd/>`, как у калькулятора) на десктопе делится по нему, а на планшете и телефоне — пополам.

Что считается подзаголовком: абзацы с `data-sub2` на главной и классы `.tp-sub`, `.tp-final__sub`, `.tp-dome-copy__sub` на партнёрских страницах. Подзаголовок в «Infinite Flow» делит пополам свой скрипт внутри `embeds/infinite-flow.html`.

### Первый экран /partner-terms/: примеры заработка

Первый экран страницы комиссий собран по макету TradeQuo_Earnings_Hero: заголовок «Your audience. Your influence. Your earnings.» и три карточки типичных партнёров. Для этого отступы зависят от высоты окна, а в невысоком окне (до 820px) заголовок чуть меньше и «сцена» карточек ниже. На телефоне (до 640px) первая кнопка тоже в первом экране (проверено на 390×737 — iPhone в Chrome). Подзаголовок на телефоне короткий: второе предложение полного (`cp.earn.subShort`, полный текст `cp.earn.sub` виден на остальных экранах). Примечание на телефоне стоит под кнопками, поэтому обе кнопки видны в первом экране (390×737: английский и большинство языков; в немецком, испанском, японском, тайском и вьетнамском вторая кнопка ниже края на 6–42px).

Кнопки первого экрана — по макетам: пилюля с круглой кнопкой-стрелкой в начале. У «Discuss your terms» чёрный фон и красный круг с белой стрелкой, у «Become a partner» красный фон и белый круг с красной стрелкой; снизу «бортик» и тень. При наведении стрелка сдвигается вперёд. В RTL круг справа, стрелка развёрнута. Стили — `.tq-earn__cta` и `.tq-earn__dot` в `partner.css`. Под ними по центру примечание о ставках, а под примечанием две кнопки: чёрная «Discuss your terms» и красная «Become a partner» (`nav.cta`, как в шапке). Обе ведут на форму заявки главной. Калькулятор стоит сразу под этим экраном.

Карточки:

| Профиль | Трейдеры | Лотов на трейдера в месяц | В месяц | В день | В год |
|---|---|---|---|---|---|
| Content creator | 23 | 12 | $2,070 | $69 | $24,840 |
| Trading community | 140 | 18 | $18,900 | $630 | $226,800 |
| Education business | 460 | 27 | $93,150 | $3,105 | $1,117,800 |

Считается так же, как в калькуляторе: трейдеры × лоты × $7.50; день — тридцатая часть месяца, год — двенадцать месяцев. Суммы записаны в разметке (`tools/i18n/commission.html`) и не пересчитываются.

Как ведут себя карточки:
- под мышью наклоняются за курсором, по ним скользит блик;
- клик, Enter или пробел выбирает карточку: красная рамка, метка «Selected», остальные две бледнеют; повторный клик снимает выбор;
- свечи на задней карточке рисует скрипт, это украшение.

Уже 1040px три карточки в ряд не помещаются, и ряд становится свайпером:
- лента идёт от края до края экрана, после свайпа карточка встаёт по центру;
- соседние карточки чуть меньше и бледнее и уменьшаются к центральной, их края видны по бокам;
- под лентой три точки, тап по точке листает к своей карточке;
- тап по боковой карточке выдвигает её в центр, тап по центральной выбирает её;
- если пролистать к другой карточке, выбор снимается.

Ширина карточки в свайпере — `--cw` в `partner.css` (78% экрана, от 280 до 380px). Масштаб и прозрачность боковых карточек считает `plan.js` по ходу прокрутки.

Стили — раздел «commission page hero» в конце `partner.css`, поведение — в `plan.js`. Тексты — ключи `cp.earn.*` в `strings/commission/<язык>.json`.

### Калькулятор комиссий

Калькулятор один и тот же на главной и на /partner-terms/, по макету Payout_Calculator_Receipt_Dark. Это тёмная панель:
- сверху заголовок и подпись страницы (главная — `calc.title`/`calc.sub`, /partner-terms/ — `cp.hero.h1`/`cp.hero.sub`);
- слева стеклянный «терминал»: два слайдера на шкале с делениями (лоты на трейдера 10–1000, активные трейдеры 1–300), переключатель Day / Month / Year и кнопка «Become a partner» на форму;
- справа чек PAYOUT, который «печатается» из серебристой щели: номер, дата, период, строка «Rebate on client volume», бесплатные комиссии, итог с подписью «TOTAL PAYOUT / MONTH» (`inv.totDay`/`inv.totMonth`/`inv.totYear`), штрихкод и штамп PAID.

Разметка — `tools/i18n/partials/calc-open.html` и `calc-body.html`: страница ставит свой заголовок между ними. Стили — раздел «Payout calculator» в конце `site.css`, логика — `startCalculator` в `landing.js`. Слайдеры — обычные `input type=range` (работают с клавиатуры) под нарисованной шкалой. Под панелью примечание `calc.note`.

На планшете и телефоне (до 900px) одна колонка: чек над терминалом, чтобы итог было видно, пока двигаешь слайдеры. Чтобы чек и терминал помещались на один экран, чек там заканчивается на итоге (штрихкода и штампа PAID нет), в терминале нет строки «Terminal · TQ-…», а подпись слайдера и его число стоят в одной строке над шкалой. На телефоне (до 640px) всё ещё плотнее: пара занимает около 620–650px по высоте и целиком видна на экране 390×664. Длинные числа и длинное слово вместо PAYOUT (например, AUSZAHLUNG) уменьшаются, чтобы влезть в чек.

Расчёт: лоты на трейдера × активные трейдеры × одна ставка за лот, $7.50. Ставка задана константой `RATE` в `startCalculator`, а число «$7.50» в тексте — в строке `inv.rebateCalc`. Если ставка меняется, правьте оба места, а заодно примеры заработка на /partner-terms/ (суммы в карточках и `cp.earn.note`).

`site/assets/js/plan.js` на /partner-terms/ запускает красный импульс по шагам процесса выплат и ведёт карточки примеров на первом экране.

Чек считает за день, месяц или год: переключатель Day / Month / Year в терминале (`[data-inv-per]`, подписи `inv.pDay`/`inv.pMonth`/`inv.pYear`). От выбора зависят сумма, строка «Rebate on client volume», число лотов, поле PERIOD и подпись над итогом. День — тридцатая часть месяца, год — двенадцать месяцев (`PER` в `startCalculator`).

### Переходы между страницами

`site/assets/js/transition.js` + блок `.tq-loader` в `site/assets/css/site.css`, разметка — `tools/i18n/partials/loader.html` (и такая же в `tools/build-pages.py`). При переходе логотип TradeQuo за ~0,46 с наливается чёрными «чернилами», на новой странице за ~0,5 с сливается, и экран гаснет. Это обычный SVG без WebGL; ссылки предзагружаются при наведении. Старый 3D-лоадер (`site/embeds/tradequo-loader.html`) больше нигде не подключён.
