# TradeQuo Partner Program: сайт

Статический сайт без сборки. Всё, что уходит на хостинг, лежит в `site/`.

```
site/
  index.html                 лендинг (Partner Program v2)
  commission-plans/ dashboard/ marketing-hub/ academy/ success-stories/
                             концепт-страницы, у каждой свой URL
  embeds/                    3D-блоки и ролики (iframe, грузятся при подходе к экрану)
  vendor/                    three.js и React — свои копии, без внешних CDN
  assets/css/site.css        стили (перенесены из дизайна один в один; в index.html встроены автоматически)
  assets/fonts/              шрифты (свои копии Google Fonts, без запросов к Google)
  assets/js/landing.js       логика лендинга: калькулятор, форма с подписью, FAQ, флип, звёзды…
  assets/js/transition.js    переход между страницами через лоадер
tools/
  pages.json                 тексты концепт-страниц
  build-pages.py             пересобирает концепт-страницы из pages.json
```

## Локальный просмотр

```
cd site && python3 -m http.server 8000
```

Откройте http://localhost:8000. Отправка формы локально выдаст ошибку: принимать заявки умеет только Netlify. Открыть `index.html` двойным кликом не получится: встроенным блокам нужен сервер.

## Публикация на Netlify

Настройки лежат в `netlify.toml`: публикуется папка `site/`, сборки нет.

**Вариант 1. Через GitHub (рекомендую): каждый пуш выкатывается сам.**
1. Запушьте репозиторий на GitHub.
2. В Netlify нажмите **Add new site → Import an existing project → GitHub** и выберите репозиторий. Поля сборки оставьте как есть: Netlify возьмёт их из `netlify.toml`.
3. Нажмите **Deploy**.

**Вариант 2. Вручную, без GitHub.** Откройте https://app.netlify.com/drop и перетащите туда папку `site/` или архив `tradequo-partners-site.zip`.

**Домен tradequopartners.com.** В Netlify откройте **Domain management → Add a domain** и добавьте `tradequopartners.com`. Дальше одно из двух:
- перенесите домен на DNS Netlify: у регистратора замените NS-серверы на те, что покажет Netlify;
- или оставьте DNS у регистратора и пропишите `A @ → 75.2.60.5` и `CNAME www → <имя-сайта>.netlify.app`.

HTTPS (Let's Encrypt) Netlify включит сам.

**Заявки с формы** уходят в Netlify Forms (форма `partner-request`). Они видны в разделе **Forms** панели Netlify. Там же можно включить уведомления на почту или в Slack: **Forms → Form notifications**. Если раздел Forms пустой, включите **Forms → Enable form detection** и передеплойте сайт.

## Что нужно решить до публичного запуска

- **Куда приходят заявки.** Сейчас форма отправляет их в Netlify Forms. Чтобы слать в CRM, поменяйте `data-endpoint="/"` у формы в `tools/i18n/landing.html` на адрес вебхука и пересоберите страницы (`python3 tools/build-i18n.py`). Поля уходят POST-запросом: `name`, `email`, `phone`.
- **Ссылки Privacy Policy и Partner Terms** пока ведут на `#`.
- **Концепт-страницы** закрыты от индексации (`noindex`), потому что тексты на них черновые. Кнопки на них, как и в дизайне, пока никуда не ведут. Когда тексты будут готовы, уберите строку `robots` в `tools/build-pages.py`, запустите `python3 tools/build-pages.py` и добавьте страницы в `site/sitemap.xml`.

## Правка концепт-страниц

Отредактируйте `tools/pages.json` и запустите `python3 tools/build-pages.py`.

## Новая версия ролика или 3D-блока из Claude Design

1. Положите новый HTML-файл в `site/embeds/` под тем же именем, например `tradequo-film.html`.
2. Запустите:
   ```
   cd tools && npm install && npm run optimize-embeds
   ```
   Скрипт переведёт файл на локальные three.js и React из `site/vendor/` и заранее скомпилирует JSX в `<имя>.app.js`. Без этого шага блок будет грузить Babel (~3 МБ) и компилировать код прямо в браузере, а страница начнёт тормозить.
3. Запустите `python3 tools/stamp-assets.py`: он обновит метки версий `?v=…` в ссылках на файлы, чтобы браузеры не показывали старую версию из кэша.
4. Закоммитьте изменения: Netlify выкатит их сам.

После любой правки в `site/assets/` или `site/embeds/` тоже запускайте `python3 tools/stamp-assets.py`. Он проставит метки версий и заново встроит `site.css` в `index.html`. `build-pages.py` делает это сам. Файлы в `assets/`, `embeds/` и `vendor/` браузеры кэшируют на год, поэтому без этого шага посетители могут не увидеть правку.

## Языки

На 18 языках собираются четыре страницы: главная, «Partner Programs» (`/programs/`), «Commission Plan» с калькулятором (`/commission-plan/`) и «Marketing Tools» (`/marketing-tools/`). Английский лежит в корне сайта, остальные языки в папках `/ar/`, `/de/`, `/zh-hans/` и т. д. (например, `/de/programs/`). Переключатель языков находится в шапке. Новые страницы открываются только из веерного меню справа внизу (на телефоне — из красной кнопки меню). Концепт-страницы (`/dashboard/`, `/marketing-hub/`, `/academy/`, `/success-stories/`) убраны из меню; файлы остались на сайте, только на английском.

- `tools/i18n/landing.html`, `programs.html`, `commission.html` — шаблоны. Вместо текста в них ключи `{{ключ}}`, а в атрибутах `{{@ключ}}`. `{{> имя}}` вставляет общий кусок из `tools/i18n/partials/` (шапка, лоадер, веерное меню, футер), `{{faq:префикс:N}}` — N карточек FAQ.
- `tools/i18n/strings/<язык>.json` — тексты главной и общих частей (меню, футер). Главный файл — `en.json`; если ключа нет в переводе, подставляется английский.
- `tools/i18n/strings/programs/<язык>.json`, `strings/commission/<язык>.json` и `strings/marketing/<язык>.json` — тексты новых страниц.
- Список страниц и пунктов веерного меню — `PAGES` и `FAN` в начале `tools/build-i18n.py`.
- `tools/i18n/languages.json` — адреса, названия в переключателе, направление письма.
- `tools/i18n/TRANSLATION_BRIEF.md` — бриф для переводчиков: тон, глоссарий, ограничения длины.

Как поменять текст:
1. Исправьте `en.json` и переводы. Каждый язык — отдельный файл с теми же ключами.
2. Проверьте переводы: `python3 tools/check-strings.py` (ключи, метки `<red>`, цифры, длина надписей на кнопках).
3. Соберите страницы: `python3 tools/build-i18n.py`. Скрипт перезаписывает `site/[<язык>/][<страница>/]index.html`, поэтому правьте шаблоны и JSON, а не готовые страницы.
4. Если менялись подписи кристаллов (`embed.crys.*`), запустите `python3 tools/make-caption-fonts.py` (шрифты для CJK) и `cd tools && npm run posters` (кадры-заглушки).

### Блок «How it works» (три шага до первой выплаты)

Один и тот же блок стоит на всех трёх страницах. На лендинге он идёт после цифр, на /programs/ — после серой подложки перед «Join 30,000+ partners», на /commission-plan/ — перед FAQ. Разметка — `tools/i18n/partials/how.html`, тексты — ключи `how.*` в `strings/<язык>.json`, анимацию линии ведёт `startHowLine` в `landing.js`. Кнопка на лендинге прокручивает к форме, а с других страниц ведёт на форму лендинга с анимацией перехода (`signupHref`/`signupNav` в `build-i18n.py`).

### Блок «Who it's for» на /programs/

Сразу после карточек программ (по макету Who_Its_For_Showcase). Слева список из пяти типов партнёров. Открытая строка рассказывает короткую историю и показывает подходящую программу («BEST FIT» — название берётся из `pp.p1.title`/`pp.p2.title`/`pp.p3.title`). Справа 3D-карусель стеклянных карточек с эмблемами (`site/embeds/who-cards.html`), она поворачивается к открытой строке. Тексты — ключи `pp.who.*` в `strings/programs/<язык>.json`. Строки сменяются каждые 6 с, пока блок на экране (`startWho` в `landing.js`): пауза при наведении и фокусе, без автосмены при «уменьшении движения». Клик по строке держит её 9 с. Список заранее занимает высоту самой длинной истории, поэтому на телефоне при смене строк ниже ничего не прыгает. Кадр-заглушка — `site/assets/posters/who-cards.webp`, перерисовка: `cd tools && node render-program-posters.mjs who`.

### Блок «Why partners choose TradeQuo» на /programs/

Восемь 3D-объектов на стеклянных подиумах, по одному на преимущество (`site/embeds/benefit-objects.html`, по макету Key_Benefits_Objects), и стеклянная карточка с текстом справа от заголовка. Активный объект поднимается, его подиум подсвечивается красным, и он проигрывает свою анимацию. Остальные слегка размыты: каждый подиум рисуется отдельным проходом. Карточка, заголовки и переводы — в шаблоне `programs.html` (ключи `pp.ben.*`, группы `pp.ben.g1`/`g2`). Подписи на чипах под подиумами — `embed.kb.1`…`embed.kb.8` в `strings/<язык>.json`. Активный пункт задаёт страница (`startKeyBenefits` в `landing.js`): каждые 2,5 с, пока блок на экране, с паузой при наведении и без автосмены при «уменьшении движения». Клик по полоске в карточке или по чипу в сцене открывает пункт и держит его 7 с. На телефоне сцена раскладывается 2×4, чипы показывают номер и иконку, а карточка уходит под сцену. Кадры-заглушки: `site/assets/posters/benefits-objects-wide.webp` (сцена 1120:720) и `benefits-objects.webp` (360:580, до 641px). После правки сцены перерисуйте их: `cd tools && node render-program-posters.mjs benefits`.

### Блок «A broker traders trust» на /programs/

Купол из шестиугольников вокруг точки TradeQuo (`site/embeds/trust-dome.html`, по макету Trust_Dome_Partners). Четыре цифры — обычный текст страницы рядом со сценой (`[data-stat]` в `programs.html`, подписи `embed.crys.*`). Пока цифры стоят по углам сцены, сцена проявляет их по очереди и рисует к ним линии от ячеек купола. На телефоне они стоят сеткой под сценой, и сцена их не трогает. Подписи рисков, которые отскакивают от купола, — `embed.dome.r1`…`r4` в `strings/<язык>.json`. Сцена стоит на первом кадре (плоское поле, как кадр-заглушка `site/assets/posters/trust-dome.webp`) и проигрывает сборку купола с начала, когда на экране оказывается половина сцены. Цифры проявляются по мере того, как загораются их ячейки; если цифры уже были на экране, когда сцена загрузилась, они остаются видны. Клик по сцене проигрывает сборку заново. Кадр-заглушка: `cd tools && node render-program-posters.mjs trust`.

### Страница Marketing Tools (`/marketing-tools/`)

Собрана в стиле остальных партнёрских страниц, шаблон — `tools/i18n/marketing.html`:
- hero: четыре инструмента на серой подложке, тёмные карточки с 3D-объектами из блока Partner perks главной (Creatives, Free TradingView, Free Trading Signals, White-Label Academy);
- каталог промо-материалов (`#library`): шесть форматов — баннеры, лендинги, видео, GIF, посты для соцсетей, логотипы и брендбук. У каждого своя иллюстрация (SVG в шаблоне), название и строка описания (`mt.lib.N.t`/`.d`). Под каталогом строка «Need something specific?»: материалы под заказ готовит менеджер (`mt.lib.custom.*`);
- **цифры в каталоге**: ключи `mt.lib.1.n`…`mt.lib.6.n` (по порядку карточек). Сейчас они пустые, и плашка с цифрой скрыта. Впишите, например, `"240+"` во все `strings/marketing/<язык>.json` и пересоберите страницы: плашка появится рядом с названием формата;
- «How to get them» (`#get`): четыре шага от Client Portal до аудитории. Первый шаг берёт тексты `how.s2.*` из блока How it works, остальные — `mt.get.2…4.*`. Шаги намеренно короткие и общие: когда будут известны детали (название раздела в портале, выбор языка и размера, код для вставки), поправьте `mt.get.*`;
- две стеклянные карточки: Live tracking и персональный менеджер;
- How it works;
- FAQ;
- финальный блок.

В тексты вошло только то, что сайт уже обещает партнёрам. Цифр (сколько баннеров, на скольких языках лендинги) нет: их нужно подтвердить, прежде чем добавлять.

Карточки инструментов берут тексты `offer.*` из `strings/<язык>.json`. Остальное — ключи `mt.*` в `strings/marketing/<язык>.json`. Часть этих ключей — копии уже переведённых строк: `mt.track.*` и `mt.mgr.*` из `pp.ben.4/5`, FAQ из `pp.faq.4`, `faq.1`, `faq.5`, `faq.3`, финал из `pp.end.*` и `cp.end.cta2/teaser`. Если меняете исходную строку, поправьте и копию.

Пункт «Marketing Tools» есть в веерном меню (`FAN` в `build-i18n.py`, подпись `fan.marketing`; для меню в некоторых языках короткий вариант, например «Kit de marketing») и в мобильном меню каждой страницы. Длинные подписи в лепестках веерного меню переносятся на вторую строку.

### Форма заявки и экран успеха

Дата в форме подставляется сама: сегодняшняя, в формате ДД / ММ / ГГГГ. После нажатия «Send request» с кнопки улетает конверт, и форма отправляет поля на `data-endpoint`. Если сервер принял заявку, форма отъезжает назад и гаснет, а на её месте собирается экран успеха по макету Partner_Form_Success:
- заголовок «Request sent.»;
- конверт с сургучной печатью и почтовым штемпелем с сегодняшней датой;
- записка от руки «Thanks, {имя}! We’ll call you within 24 hours.»;
- три шага (Sent → Call → Start earning);
- кнопки «Partner Programs» и «Commission calculator».

Если сервер ответил ошибкой, экран успеха не показывается: под кнопкой появляется сообщение, и кнопку можно нажать снова.

- Разметка — `tools/i18n/partials/form-done.html`.
- Стили — раздел «Sign-up success screen» в `site.css`.
- Логика — `startForm` в `landing.js`.
- Тексты — ключи `done.*` в `strings/<язык>.json`. Заголовок берётся из `form.sent`, первая кнопка из `fan.programs`.

Обещание «позвоним в течение 24 часов» стоит в `done.call` и `done.s2d`. Если срок другой, поменяйте эти строки во всех языках.

Посмотреть экран успеха, ничего не отправляя: откройте главную с `?preview=sent` (например, `/de/?preview=sent`), заполните email и нажмите кнопку.

### Объёмные кнопки на /programs/

Три кнопки по макетам CTA_Ionic_Capital, CTA_Pedestal и CTA_Trust_Dome, все ведут на форму заявки лендинга:
- «Apply as a partner» с серебряными завитками стоит под списком в блоке «Who it's for»;
- «Start earning» на постаменте стоит под сценой с объектами в Key Benefits;
- «Join 30K+ partners» под стеклянным куполом стоит в блоке «A broker traders trust», рядом с «Read the reviews».

Это обычный HTML и CSS без WebGL. Стили — раздел «3D call-to-action buttons» в конце `partner.css`. Наведение, наклон за курсором и нажатие ведёт `startCta3d` в `landing.js`. Он же подгоняет завитки Ionic под ширину надписи. Подписи — ключи `pp.cta.apply`, `pp.cta.start`, `pp.cta.join` в `strings/programs/<язык>.json`. На узком экране длинная подпись переносится на вторую строку.

### Автоперевод браузера

Автоперевод (например, в Chrome) разрешён по умолчанию. В конце меню языков есть переключатель «Auto-translate»: если посетитель его выключит, выбор запоминается в браузере (`localStorage`), страница перезагружается и больше не переводится автоматически (`translate="no"` и `<meta name="google" content="notranslate">` ставит скрипт в `partials/head.html`).

### Калькулятор комиссий

`site/assets/js/plan.js`: активные клиенты × лоты на клиента × одна ставка за лот, $7.50 (как в исходном дизайне калькулятора лендинга). Уровней (Starter/Gold/Elite) нет. Ставка задана константой `RATE` в `plan.js` и в `startCalculator` в `landing.js`; число «$7.50» в разметке — в `commission.html` (смета) и в строке `inv.rebateCalc` лендинга. Если ставка меняется, правьте все эти места.

### Переходы между страницами

`site/assets/js/transition.js` + блок `.tq-loader` в `site/assets/css/site.css`, разметка — `tools/i18n/partials/loader.html` (и такая же в `tools/build-pages.py`). При переходе логотип TradeQuo за ~0,46 с наливается чёрными «чернилами», на новой странице за ~0,5 с сливается, и экран гаснет. Это обычный SVG без WebGL; ссылки предзагружаются при наведении. Старый 3D-лоадер (`site/embeds/tradequo-loader.html`) больше нигде не подключён.
