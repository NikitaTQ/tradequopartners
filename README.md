# TradeQuo Partner Program: сайт

Статический сайт без сборки. Всё, что уходит на хостинг, лежит в `site/`.

```
site/
  index.html                 лендинг (Partner Program v2)
  commission-plans/ dashboard/ marketing-hub/ academy/ success-stories/
                             концепт-страницы, у каждой свой URL
  embeds/                    3D-блоки и ролики (iframe, грузятся при подходе к экрану)
  vendor/                    three.js и React — свои копии, без внешних CDN
  assets/css/site.css        стили (перенесены из дизайна один в один; в index.html встроены автоматически)
  assets/fonts/              шрифты (свои копии Google Fonts, без запросов к Google)
  assets/js/landing.js       логика лендинга: калькулятор, форма с подписью, FAQ, флип, звёзды…
  assets/js/transition.js    переход между страницами через лоадер
tools/
  pages.json                 тексты концепт-страниц
  build-pages.py             пересобирает концепт-страницы из pages.json
```

## Локальный просмотр

```
cd site && python3 -m http.server 8000
```

Откройте http://localhost:8000. Отправка формы локально выдаст ошибку: принимать заявки умеет только Netlify. Открыть `index.html` двойным кликом не получится: встроенным блокам нужен сервер.

## Публикация на Netlify

Настройки лежат в `netlify.toml`: публикуется папка `site/`, сборки нет.

**Вариант 1. Через GitHub (рекомендую): каждый пуш выкатывается сам.**
1. Запушьте репозиторий на GitHub.
2. В Netlify нажмите **Add new site → Import an existing project → GitHub** и выберите репозиторий. Поля сборки оставьте как есть: Netlify возьмёт их из `netlify.toml`.
3. Нажмите **Deploy**.

**Вариант 2. Вручную, без GitHub.** Откройте https://app.netlify.com/drop и перетащите туда папку `site/` или архив `tradequo-partners-site.zip`.

**Домен tradequopartners.com.** В Netlify откройте **Domain management → Add a domain** и добавьте `tradequopartners.com`. Дальше одно из двух:
- перенесите домен на DNS Netlify: у регистратора замените NS-серверы на те, что покажет Netlify;
- или оставьте DNS у регистратора и пропишите `A @ → 75.2.60.5` и `CNAME www → <имя-сайта>.netlify.app`.

HTTPS (Let's Encrypt) Netlify включит сам.

## Новая версия ролика или 3D-блока из Claude Design

1. Положите новый HTML-файл в `site/embeds/` под тем же именем, например `tradequo-film.html`.
2. Запустите:
   ```
   cd tools && npm install && npm run optimize-embeds
   ```
   Скрипт переведёт файл на локальные three.js и React из `site/vendor/` и заранее скомпилирует JSX в `<имя>.app.js`. Без этого шага блок будет грузить Babel (~3 МБ) и компилировать код прямо в браузере, а страница начнёт тормозить.
3. Если в файле есть картинки, встроенные как `data:image/png;base64,…` (в ролике это `window.TQ_ASSETS`), пережмите их без потерь в WebP (Pillow: `save(..., 'WEBP', lossless=True, exact=True, method=6)`; пиксели остаются те же). Ролик рисует каждую картинку через `new Image()` и canvas, формат ему не важен. Так `tradequo-film.html` стал легче на треть (302 → 203 КБ в сжатом виде).
4. Если это ролик (`tradequo-film.html`): на главной он идёт видеофайлом, снятым с этого файла, поэтому перезапишите видео: `cd tools && node render-film.mjs` (несколько минут; см. «Ролик на главной — видео» ниже).
4а. Если это Infinite Flow — переснимите его заглушки: при запущенном локальном сервере на :8772 `node tools/flow-poster/shoot.cjs && python3 tools/flow-poster/webp.py` (нужен Playwright). Если это ролик — обновите его заглушку, кадр 0,4 с: `ffmpeg -ss 0.4 -i site/assets/film/tradequo-film-1080.mp4 -frames:v 1 poster.png`, затем в webp как `site/assets/film/tradequo-film-poster.webp`.
5. Запустите `python3 tools/stamp-assets.py`: он обновит метки версий `?v=…` в ссылках на файлы, чтобы браузеры не показывали старую версию из кэша.
6. Закоммитьте изменения: Netlify выкатит их сам.

### Когда грузятся 3D-блоки и ролик

Главное правило (ноябрь 2026): **прокрутка не должна подтормаживать никогда, и всё должно быть на месте**, даже если посетитель за две секунды долистал страницу до конца. Встроенные 3D-блоки (кристаллы, Infinite Flow, купол) — страницы того же сайта в `iframe`, и всё, что они делают, идёт в том же потоке, что и прокрутка страницы. Поэтому:
- **запуск 3D**: страница Infinite Flow встраивается сразу после первой отрисовки главной (`requestAnimationFrame` в `startEmbeds`; раньше — после события `load`, когда догрузятся все картинки) и сразу грузит свой кадр и ролик (ниже) — это только сеть. three.js главная просит ещё из `<head>` (`<link rel="preload" … fetchpriority="low">` в `tools/i18n/landing.html`), а встройки заранее объявляют свои модули (`<link rel="modulepreload">` в `embeds/infinite-flow.html` и `embeds/crystals.html`; у кристаллов — с хешами из import map, иначе браузер качал бы модуль второй раз): раньше `three.module.min.js` только после загрузки сообщал, что ему нужен `three.core.min.js`, — второй круг по сети. Сам запуск — исполнение three.js и сборка сцены, единственная тяжёлая работа блока, — ждёт первого действия посетителя на странице (прокрутка, колесо, касание, клик, клавиша, движение мыши) или того, что блок на экране (`window.__tqGo` в `embeds/infinite-flow.html`; модуль сцены импортирует three.js только после него). Поэтому просто открытая страница (и её замер в Lighthouse/PageSpeed, где видеокарты нет и компиляция шейдеров занимает секунды) за 3D не платит. Дальше подготовка идёт мелкими шагами, каждый — отдельная задача (`scheduler.yield`), подряд: создание WebGL, окружение, материалы, геометрия, заказ всех шейдеров (компилируются параллельно, в фоне, `KHR_parallel_shader_compile`; включая все материалы монет — у монеты их три), текстуры в видеокарту, первый кадр (за экраном). Запросы логов шейдеров при первом кадре выключены (`renderer.debug.checkShaderErrors`, как советует three.js для продакшена: шестьдесят ожиданий видеокарты подряд; `?debug` в адресе встройки включает их обратно);
- **«восьмёрка» не стоит ни секунды**: компиляция шейдеров зависит от видеокарты (на Windows стеклянные материалы собираются дольше всего), поэтому до готовности живой сцены на её месте идёт **ролик этой же сцены** — её первые 8 секунд, снятые с неё самой кадр за кадром (`assets/flow/motion-wide.mp4` 1920×1080, 1,0 МБ, и `motion-square.mp4` 1050×1050 для телефонов, 508 КБ; 60 кадров/с, как живая сцена; H.264 — его декодирует видеокарта, странице это почти ничего не стоит). Анимация сцены зависит только от времени, поэтому живая сцена, когда готова, начинает **с того же момента, на котором ролик** (`window.__tqMotion` в `embeds/infinite-flow.html`; сначала сцена один раз рисуется невидимой — в этом кадре вся оставшаяся цена первого рисования, — потом заново берётся время ролика и сразу рисуется этот момент), проявляется поверх него за 0,6 с, на это время идёт с ним в ногу, и ролик убирается — подмена не видна. У холста белая подложка (`.if-scene canvas`): полупрозрачные тени и отражения сцены при проявлении не смешиваются с роликом под ними. Под роликом — неподвижный кадр t = 0 (`poster-wide.webp` / `poster-square.webp`, он же первый кадр ролика), пока ролик не начал играть. Ролик играет, только пока блок на экране; при «уменьшить движение» и «экономии трафика» его нет (стоит кадр). Подписи выплат над монетами рисует страница, в ролике их нет: первая появляется на 3,5 с, к этому моменту живая сцена обычно уже работает. Ролик — 8 секунд: короче без скачка не зациклить (монеты разные, сцена целиком повторяется только через 24 с), и если на очень медленном устройстве живая сцена не готова и после 8 секунд показа, ролик стоит на последнем кадре. Снимают `tools/flow-poster/motion.cjs` (сцена с `?shoot` рисует любой момент по `window.__tqRenderAt(t)`) и `motion.py` (кодирование, CRF 24); неподвижный кадр — `shoot.cjs` + `webp.py`. Поменяли сцену — переснимите и то и другое и запустите `python3 tools/build-i18n.py`;
- **заглушки** у остальных: кристаллы — заглушка страницы, как и раньше; ролик TradeQuo — `poster` с кадром 0,4 с (`assets/film/tradequo-film-poster.webp`; ролик открывается 0,4 с белого, поэтому первый показ начинается с 0,4 с — с той же картинки). Живая сцена проявляется поверх заглушки (0,6 с);
- у кристаллов текстуры надписей 1024px по ширине (было 2048 на десктопе — в 4 раза больше пикселей без видимой разницы: плашка на экране 150–200px), карта логотипа (миллион пикселей) считается в четыре приёма, а буфер кадра не сохраняется между кадрами (`preserveDrawingBuffer` — только для скриншотов в редакторе, `?ui`);
- разрешение, которое тянет видеокарта: Infinite Flow, кристаллы, «чёрная дыра» и сеть на IB Tools (`ib-hole.js`, `ib-insights.js`) следят за частотой кадров, пока они на экране; если 20 кадров подряд идут медленнее ~45 в секунду, рисуют проще: разрешение ступенями вниз до 1x (Infinite Flow и кристаллы — потом и буфер преломления стекла; сеть — сначала лёгкие тени, как на телефонах). Обратно в течение визита не поднимается; на мощной видеокарте всё остаётся в полном качестве;
- звёзды за FAQ: цвет каждой звезды считается один раз на размер, а не в каждом кадре;
- ролик — видео (см. ниже): после первого действия он только скачивается (это не нагружает страницу), играет, пока на экране;
- прыжок по оглавлению страницы или наверх пролетает блоки, не запуская их: запускаются те, что рядом с местом, где страница остановилась;
- блок, скрытый через `display: none` (ролик на телефонах), не грузится никогда.

Проверка (Chromium в тестовой среде без видеокарты — WebGL там рисует процессор и без параллельной компиляции шейдеров, поэтому абсолютные времена в разы больше настоящих): «открыть главную и сразу долистать до „восьмёрки“» — раньше на месте блока 12–13 с стояла неподвижная картинка; теперь ролик играет с момента прихода (проверено и с искусственно задержанным на 5 с three.js), а живая сцена подхватывает его кадр в кадр (сравнение снимков: ролик 2,046 с — холст 2,050 с; на телефоне 1,696 — 1,700). Без действий посетителя кадр «восьмёрки» загружен, ролик в буфере, three.js не исполнялся. Lighthouse главной — 100 (мобильный) и 100 (десктоп), блокировка потока 40 и 0 мс; запуск 3D сразу после отрисовки, без ожидания действия, давал здесь 69 и 69. Где эта среда тормозит прокрутку, тормозит сама отрисовка 3D процессором (старая сборка с уже живой «восьмёркой» листается так же). Programs и Partner Terms — без блокировок. Аудит Lighthouse: главная, Programs, Partner Terms, IB Tools — 89–100 баллов; Marketing Tools (сцена со шторами грузилась сразу и блокировала поток на 2–8 с) удалена.

Код — `startEmbeds`, `holdEmbeds` и `startFilm` в `site/assets/js/landing.js`, пометки `data-warm` — в `tools/i18n/landing.html`, запуск по шагам — в самих `embeds/*.html`.

### Ролик на главной — видео

Ролик TradeQuo Partner Program (24,2 с, по кругу) на главной — видеофайл (60 кадров/с, H.264: живой ролик двигался каждый кадр экрана, на 30 движение шло рывками) в `site/assets/film/`: `tradequo-film-1440.mp4` (2560×1440) там, где ролик занимает на экране больше ~1700 физических пикселей в ширину (ретина, масштаб 150%), и `tradequo-film-1080.mp4` (1920×1080, уменьшен из 1440 по Ланцошу) на остальных: браузер уменьшает видео простым способом, 1440 на экране в ~1240 точек рябил бы на тонких линиях, а 1080 на ретине растягивался бы и мылился; каждый посетитель качает один файл (выбор — в `startFilm`). Для браузеров без H.264 — `tradequo-film-1080.webm` (VP9). а не живая сцена. Живой ролик (`site/embeds/tradequo-film.html`: React, three.js и стеклянный логотип, который перерисовывается каждый кадр) был самым тяжёлым на странице, и на стыке с Infinite Flow (оба на экране) страница тормозила. Видео декодирует видеокарта — нагрузки почти нет. Видео снято с живого ролика кадр за кадром (`tools/render-film.mjs`), поэтому выглядит так же. Снято без плёночного зерна: зерно (движущийся шум по всему кадру) хуже всего поддаётся сжатию и съедает качество тёмных сцен (блоки на световых полосах, пропавшая сетка из точек). Его рисует страница поверх видео — та же текстура шума, что в ролике, сдвиг 24 раза в секунду, наложение overlay с силой 0,07, появляется на 1,7–2,2 с (`startFilm`, слой `.tq-film__grain` двигается через transform, без перерисовки). Сжатие подобрано под тёмный ролик (CRF 21, film-тюнинг x264, AQ с упором на тёмные места), цвета переводятся в BT.709, которым помечено видео (иначе красный уезжает). Поверх него — кнопки плеера ролика, как были: назад и вперёд на 1,5 с, пауза/воспроизведение (затемнены, пока курсор не над роликом и он не на паузе). Играет, пока на экране, вне экрана стоит; при «уменьшить движение» не запускается сам, стоит последняя сцена (23,5 с), пока не нажать воспроизведение. Разметка — `#film` в `tools/i18n/landing.html`, стили — раздел «the partner film» в `site.css`, код — `startFilm` в `landing.js`. Живой ролик остаётся в `site/embeds/` как исходник видео: поменяли его — перезапишите видео (`cd tools && node render-film.mjs`, потом `python3 tools/build-i18n.py`).

Стеклянный логотип TradeQuo в левой колонке FAQ на главной — статичный кадр, а не 3D-сцена: `site/assets/faq-logo.webp` (800×744, вдвое больше блока 400×372; прозрачный фон, 79 КБ). ### Ролик на телефонах

На телефонах (до 640px) блока с роликом на главной нет: секция `#film` скрыта, её видео не грузится. Раньше там шло MP4 этого ролика (1,3 МБ — больше половины веса мобильной главной); его, скрипт и стили убрали (в истории git — коммит «Phones: partner film as an MP4…»). Десктоп и планшет показывают живой ролик `tradequo-film.html`. Ради экономии памяти подписи в 3D-кристаллах на телефоне рисуются в текстурах шириной 1024px вместо 2048 (`TX` в `embeds/crystals.html`).

После любой правки в `site/assets/` или `site/embeds/` тоже запускайте `python3 tools/stamp-assets.py`. Он проставит метки версий и заново встроит `site.css` (и `partner.css`) в страницы. `build-i18n.py` запускает его сам. Файлы в `assets/`, `embeds/` и `vendor/` браузеры кэшируют на год, поэтому без этого шага посетители могут не увидеть правку.

Что ещё делает `stamp-assets.py` ради скорости:
- встраивает CSS без комментариев (в исходных `site.css` и `partner.css` они остаются): страницы на 14–22% легче;
- встраивает в страницу только те правила, которые на ней могут сработать (`used_css` в `stamp-assets.py`): в `site.css` и `partner.css` лежат стили всех страниц, а правило остаётся, если все классы хотя бы одного его селектора есть на странице — в разметке (`class="…"`) или в скриптах, которые она загружает (встроенные и `assets/js/*.js`; скрипты добавляют классы на ходу, иногда собирая их из начала имени, это тоже учитывается). Классы внутри `:not()`, `:is()`, `:where()`, `:has()` не требуются; правила без классов, `@font-face`, `@keyframes`, `@property` остаются всегда. Внутренние страницы так стали вдвое легче (сжатая /programs/ — 25 КБ вместо 46). Править стили — как раньше, в `site.css` / `partner.css`: сборка сама разложит их по страницам. Если класс навешивается скриптом, которого страница не загружает (например, из встроя-iframe на родителя), впишите этот класс в разметку или в скрипт страницы, иначе его правило выпадет;
- не ставит метку на файлы в `vendor/`: в имени папки уже есть версия библиотеки, а модули three.js импортируются по точным адресам (import map, импорты внутри самой библиотеки) — предзагрузка с `?v=` была бы другим адресом и вторым скачиванием;
- метка ставится и на `data-src-*` (например, `data-src-square` у ролика «восьмёрки» для телефонов);
- ставит метку версии и на шрифты — в `url(…woff2)` во встроенном CSS, в шрифтах 3D-блоков и в `<link rel="preload">` (одна и та же метка, поэтому предзагрузка и `@font-face` — один запрос). Поэтому шрифт можно перезаписать под тем же именем (как делает `h1-fonts.py`): посетители получат новый, а не годовалую копию из кэша.

Встроенный CSS у всех страниц, включая 404 и концепт-страницы. Каждая страница заранее подгружает латиницу Inter, шрифт своего H1 и, где нужно, кириллицу/вьетнамский Inter или арабский/тайский шрифт (`h1_preload` и `font_css` в `build-i18n.py`) — заголовок не перескакивает, когда шрифт приходит.

## Отступы между блоками: один на весь сайт

Между блоками каждой страницы одно расстояние — `--tq-gap` в `site.css`: от конца содержимого одного блока до начала содержимого следующего (за образец когда-то взят переход «видео → Infinite Flow» на главной, 190px при ширине 1440). С ноября 2026 на планшетах и десктопах он на 20% меньше, чем был: 202px на десктопе (было 252), на экранах от 641px — по ширине экрана (`clamp(102px, 14vw, 202px)`, было `clamp(128px, 17.5vw, 252px)`); на телефонах (до 640px) не менялся — 128px. Число меняется в одном месте — `:root` в начале `site.css`; ещё оно повторено в `ib-hole.js` (`capTop`, подпись «чёрной дыры» на IB Tools). Каждый блок держит половину (`--tq-half`) над своим содержимым и под ним: `.tp-sec`, «How it works», финальный блок, блоки главной, IB Tools. Где содержимое сидит глубже, это учтено на месте:
- плавные переходы светлое ↔ тёмное (тёмный хвост под «What we offer» на главной, переходы к тёмным перкам на Partner Programs) длиной ровно в отступ: содержимое с обеих сторон стоит у концов перехода; у сцены с занавесом уже 1200px последняя строка — её кнопка, под ней своё тёмное (`bottom` у `.tq-mts__copy`), поэтому переход снизу короче на него (не меньше 48px);
- полноэкранные блоки без «высоты в экран» (Network + clients, сеть Sub-IB на IB Tools; «You bring the audience» на главной) — их отступы задаёт `--tq-half`;
- блок копи-трейдинга на IB Tools на телефонах (до 640px, ноябрь 2026): руки с телефонами стоят в 60px под кнопкой «Explore copy trading», а не у низа экрана; сцена высотой ровно по словам и рукам (`--sh`, меряет скрипт под блоком в `ibtools.html`), сам блок — `--sh` + 210svh прокрутки, так что он короче на пустое место, которое было между кнопкой и руками; размер рук считается от высоты окна, как раньше;
- сцены, закреплённые при прокрутке: под видео на главной — остаток отступа до заголовка Infinite Flow (он на ~115px внутри сцены, на телефоне фильма нет — отступ идёт от трёх шагов, `#how` в `site.css`; до перестановки блоков в ноябре 2026 — от отзывов); сцена с руками на IB Tools держит отступ своими полями, с любым соседом: от 1200px телефон в ней виден на ~226px от верха, поэтому она заходит на половину отступа над ней на остаток (`margin-top: calc(var(--tq-half) - 226px)`), а под ней — половина (руки доходят до её низа); уже 1200px её слова стоят сразу под шапкой (76px), а руки стоят внизу экрана, в 24px от его низа (оговорки под ними больше нет), поля — половина минус 76 и минус 24. Чтобы в полях не просвечивал белый, `main` страницы IB Tools — серый блоков (`.tq-ibpage`, #e9eaec); у «чёрной дыры» подпись стоит на половине отступа от верха блока (`ib-hole.js`), а кнопка под шагами — на половине от низа;
- карточки (серая «A broker clients trust», тёмные Payouts, Materials, финальный блок) — отступ считается до их края.
От последнего блока до линии подвала — половина отступа. Проверено скриптом на всех страницах при 1440, 1024 и 390px (ноябрь 2026, после уменьшения): на десктопе на всех обычных границах 199–202px (было 249–252), при 1024 — 141–144px (было 177–179), на телефоне — 126–128px, как раньше; сцены и блоки со своими полями уменьшились на ту же величину (сцены — при экране 1440×900 и 390×844; на экранах другой высоты отступ у сцен может отличаться на несколько десятков пикселей, потому что их содержимое стоит по центру экрана).

Концепт-страницы (`/dashboard/`, `/marketing-hub/`, `/academy/`, `/success-stories/`) убраны из меню; файлы остались на сайте, только на английском.

- `tools/i18n/landing.html`, `programs.html`, `commission.html` — шаблоны. Вместо текста в них ключи `{{ключ}}`, а в атрибутах `{{@ключ}}`. `{{> имя}}` вставляет общий кусок из `tools/i18n/partials/` (шапка, лоадер, веерное меню, футер), `{{faq:префикс:N}}` — N карточек FAQ. `{{lang}}` — язык для атрибута `lang` (`zh-Hans`), `{{code}}` — код языка в путях к файлам (`zh-hans`); кадры-заглушки кристаллов называются по `{{code}}`.
- `tools/i18n/strings/<язык>.json` — тексты главной и общих частей (меню, футер). Главный файл — `en.json`; если ключа нет в переводе, подставляется английский.
- `tools/i18n/strings/programs/<язык>.json`, `strings/commission/<язык>.json`, `strings/marketing/<язык>.json` и `strings/ibtools/<язык>.json` — тексты новых страниц.

- `tools/i18n/languages.json` — адреса, названия в переключателе, направление письма.
- `tools/i18n/TRANSLATION_BRIEF.md` — бриф для переводчиков: тон, глоссарий, ограничения длины.

Как поменять текст:
1. Исправьте `en.json` и переводы. Каждый язык — отдельный файл с теми же ключами.
2. Проверьте переводы: `python3 tools/check-strings.py` (ключи, метки `<red>`, цифры, длина надписей на кнопках).
3. Соберите страницы: `python3 tools/build-i18n.py`. Скрипт перезаписывает `site/[<язык>/][<страница>/]index.html`, поэтому правьте шаблоны и JSON, а не готовые страницы.
4. Если менялись подписи кристаллов (`embed.crys.*`), запустите `python3 tools/make-caption-fonts.py` (шрифты для CJK) и `cd tools && npm run posters` (кадры-заглушки).

Точки текстур записаны в `GEO`; путь к текстуре — атрибут `data-glass` карточки (с меткой версии, как у предзагрузки). **Всё это происходит до первой отрисовки**: скрипт встроен в страницу сразу после карточек (`tools/i18n/partials/prog-cards.html`, подключён в `programs.html`), а текстуры запрашиваются заранее из `<head>` (`<link rel="preload" as="image" fetchpriority="high">`). Раньше это делала функция `startProgCards` в `landing.js`, которая запускается только после разбора всей страницы: при входе на /programs/ сначала показывались серые плиты без стекла с невыровненными рядами, а стекло появлялось через ~0,3–1 с (из-под заставки перехода уже было видно). После загрузки шрифтов (они подменяют запасные уже после первой отрисовки) скрипт пересчитывает всё ещё раз, а шрифт названий (H2) на /programs/ тоже подгружается заранее (`h2Preload` в `build-i18n.py`), чтобы названия сразу были в нём. Lighthouse /programs/: 99 (мобильный, было 89) и 100, смещение макета 0,007 и 0,008. Для арабского текстура зеркалится. На телефоне (до 640px) у второй карточки срез угла выходит на верх правее (на 79% ширины, а не на 53%), чтобы шов не заходил на название в одну строку (`tx` в скрипте карточек); эффекты шва те же — это та же текстура. Шрифты в блоке — по схеме Syncopate + Inter. Названия программ (Introducing Broker, Partner Network, White Label) набраны шрифтом заголовков разделов сайта (класс `tq-h2`: Syncopate заглавными с разрядкой или похожий шрифт для языка); размер у трёх названий одинаковый — самый мелкий из тех, что понадобились, чтобы длинное слово влезло (`data-fitw`, затем `sameNames` в скрипте карточек), и название не заходит на шов стекла. Остальное в карточках набрано Inter (вариативный, веса 300–700; файлы `site/assets/fonts/inter-*.woff2`, на /programs/ латиница Inter подгружается заранее). Номер и крупная цифра — с цифрами одинаковой ширины (`tabular-nums`; на остальной текст не включено, потому что у Inter от этого расширяется дефис). Название и крупная цифра в макете жирнее 700, а Inter загружен до 700, поэтому им добавлена тонкая обводка своим цветом. На телефоне в карточках нет текста меньше 16px, кроме номера и надписи над цифрой (13px). Арабский, тайский и CJK Inter не поддерживает: см. «Шрифты: Inter + Syncopate».

Three ways to earn.») — тоже по схеме: Syncopate 700 заглавными с разрядкой 0,15em, каждое предложение с новой строки (на телефоне идут подряд, чтобы широкий шрифт занимал меньше строк). Слово, не влезающее в экран, уменьшается (`data-fitw`). В Syncopate только латиница, и нет румынской «Ș», поэтому для других языков взяты похожие широкие акцидентные шрифты: Unbounded — украинский, вьетнамский, румынский; Reem Kufi — арабский; Prompt — тайский; Dela Gothic One — японский; Black Han Sans — корейский; ZCOOL QingKe HuangYou — упрощённый китайский; Noto Sans TC Black — традиционный (в ZCOOL нет иероглифа 眾). ### Форма заявки и экран успеха

На десктопе (от 900px) порядок в форме такой: имя, email, телефон, затем кнопка «Send request» (строки согласия «By signing and submitting this form, you agree to our Privacy Policy and Partner Terms» в форме нет: её убрали по просьбе владельца в ноябре 2026 на всех 18 языках — разметку в `landing.html` и строку `form.consent`), под ними дата и три пункта (UP TO 87% OF SPREAD …). Так «Send request» помещается в первый экран от 1920×1080. На 1440×900 кнопка пока ниже края на ~90px. Порядок меняет только CSS (`order` в конце `site.css`), на телефоне форма идёт в порядке разметки.

Мобильное меню (красная кнопка справа внизу) пропускает нажатия сквозь себя, пока закрыто: нажимаются только сама кнопка и, когда меню открыто, его ссылки (`[data-fab] { pointer-events: none }` в `site.css`). Раньше закрытое меню невидимо перекрывало правую нижнюю половину экрана, и нажатия там пропадали. На всей странице стоит `touch-action: manipulation`: iOS не ждёт двойного тапа для зума, и быстрые повторные нажатия не теряются. В RTL (арабский) кнопка меню тоже стоит у правого края: колонка меню выравнивается по правому краю (`[dir="rtl"] [data-fab]` в `site.css`), раньше кнопка оказывалась примерно в 100px от края. Открытое меню закрывается нажатием в любое место вне его и клавишей Escape; после Escape фокус возвращается на кнопку (`startFab` в `landing.js`).

На телефонах (до 640px) у всего, что нажимают, зона нажатия не меньше 44px, как советуют Apple и Google. Мелкие элементы выглядят как раньше, но принимают нажатия чуть шире своих границ: Day/Month/Year на счёте, ссылка «See the commission plan», логотип. Кнопки языка и «Become a partner» в шапке — 44px. Точки под свайперами — кнопки 44×44 с маленькой точкой внутри. Исключение — ссылки Privacy/Terms внутри текста под формой: по правилам WCAG ссылкам внутри текста это не нужно. Мелкий текст на телефонах не меньше 11px для подписей капсом и моноширинных меток и не меньше 12px для обычного текста: мелкий шрифт в футере, метки на счёте, на карточках заработка и в отзывах. Правила собраны в конце `site.css` и в разделах счёта, калькулятора и карточек заработка (`partner.css`).

Код страны в поле телефона выбирается: поверх флага и кода лежит невидимый нативный список, поэтому на телефоне открывается системный выбор. В списке 243 страны, названия на языке страницы (их даёт браузер, `Intl.DisplayNames`), отсортированы по имени. По умолчанию ОАЭ (+971). Выбор уходит в заявке полем `phone_code`, например `DE +49`. Подсказка в поле номера подстраивается под страну: это пример мобильного номера этой страны в том виде, как его пишут после кода (для +971 — «50 123 4567», для +1 — «201 555 0123», для +49 — «1512 3456789»), тоже из `libphonenumber-js`. Телефонные коды взяты из `libphonenumber-js`, флаги — SVG из `flag-icons` (оба пакета под лицензией MIT, лицензия флагов лежит в `site/assets/flags/LICENSE`). Коды и примеры номеров — константа `DIAL` в `startDial` (`landing.js`, формат `ISO|код|пример;…`), флаги — `site/assets/flags/<код>.svg`, страница грузит только флаг выбранной страны.

**UTM-метки — 30 дней** (ноябрь 2026). Если посетитель пришёл по ссылке с метками (`utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`) на любую страницу и любой язык, они сохраняются в cookie `tq_utm` (только наш сайт, без сторонних сервисов) на 30 дней с момента перехода. Вернётся в эти 30 дней без меток — например, напрямую или из закладки — заявка всё равно придёт с источником: в письме Netlify поле Utm Source (пустое, если меток не было), затем Name, Email, Phone Code, Phone. Остальные метки (medium, campaign, term, content) cookie хранит, но в заявку не отправляет — так решено в ноябре 2026, чтобы в письме было только нужное; чтобы вернуть какую-то, добавьте её скрытое поле в форму и в `formBody`. Новая ссылка с метками заменяет старые (засчитывается последний переход), и 30 дней отсчитываются заново; заход без меток ничего не меняет. Код: строка в `tools/i18n/partials/head.html` (на концепт-страницах та же строка из `tools/build-pages.py`) сохраняет метки, `formBody` в `landing.js` добавляет их к заявке, а скрытое поле `utm_source` в форме (`landing.html`) нужно Netlify: он сохраняет только те поля, которые увидел в HTML при деплое. Срок хранения — `max-age=2592000` (30 дней в секундах). Cookie работает на весь сайт (`path=/`): метка с главной засчитается и при заявке, отправленной через неделю после захода на другую страницу. Не сохранится только при другом устройстве или браузере, в режиме инкогнито и после очистки cookie. **Safari (iPhone, Mac):** cookie, которую записал скрипт страницы, он хранит не больше 7 дней (после клика из рекламной сети — 1 день). Поэтому страница сразу после записи вызывает `/api/utm` (`netlify/edge-functions/utm.js`), и наш сервер ставит ту же cookie заголовком `Set-Cookie`: такую Safari хранит все 30 дней. Вызов идёт только при заходе по ссылке с метками, на остальные заходы функция не тратится. Локально `/api/utm` нет — остаётся cookie от скрипта.

**Что приходит в письме Netlify** (ноябрь 2026): Name, Email, Phone Code (например, «LT +370») и Phone — номер уже с кодом страны («+370 52595646»: его добавляет `formBody` в `landing.js` при отправке). Раньше над номером стояла странная подпись «+971 الهاتف United Arab Emirates (+971)»: Netlify берёт название поля из текста `<label for=…>`, а в нём был весь блок кода страны со значением по умолчанию (и на языке той страницы, которую он прочитал). Теперь у подписи телефона нет `for`, и Netlify называет поле по `name` — «Phone», как Name и Email; для скринридеров у поля номера `aria-label`. Подписи полей Netlify обновляет при каждом деплое.

**Страна по умолчанию — страна посетителя** (ноябрь 2026; раньше всегда ОАЭ, +971). Сразу ставится догадка по языку страницы (de — Германия, fr — Франция, es — Испания, pt — Бразилия, ar — ОАЭ, ja — Япония, zh-hans — Китай, zh-hant — Тайвань и т. д.; на английской — по региону языка браузера, например en-GB — Великобритания, иначе ОАЭ), затем страна по IP: её отдаёт сам Netlify — функция `netlify/edge-functions/geo.js` по адресу `/api/geo` (геолокация Netlify, без сторонних сервисов, ничего не хранит). Ответ запоминается на время визита (`sessionStorage`), чтобы не спрашивать на каждой странице. Если посетитель уже сам выбрал код, его выбор не меняется. Локально (без Netlify) `/api/geo` нет — остаётся догадка по языку. Код — `startDial` в `landing.js`. Netlify находит функцию сам: папка `netlify/edge-functions` в корне репозитория, отдельно включать ничего не нужно.

Шрифт в полях формы — 16px. Меньше делать нельзя: Safari на iPhone и iPad увеличивает страницу, когда нажимаешь на поле с шрифтом меньше 16px.

### Заголовки и подзаголовки

Подзаголовки под заголовками всегда в две строки. Это делает `startTwoLine` в `landing.js`:
- ширина подзаголовка ставится в rem, примерно в половину длины текста в одну строку, а `text-wrap: balance` выравнивает строки;
- если колонка уже́ этой половины (планшет, боковая колонка FAQ), шрифт подзаголовка уменьшается ровно настолько, чтобы влезли две строки, но не меньше 65% и не меньше 15px;
- если и так не влезает (длинные подзаголовки на телефонах, абзац у купола на /programs/), размер не трогается, и текст занимает больше строк;
- подзаголовок с ручным переносом (`<brd/>`, как у калькулятора) на десктопе делится по нему, а на планшете и телефоне — пополам.

Что считается подзаголовком: абзацы с `data-sub2` на главной и классы `.tp-sub`, `.tp-final__sub`, `.tp-dome-copy__sub` на партнёрских страницах. Подзаголовок в «Infinite Flow» делит пополам свой скрипт внутри `embeds/infinite-flow.html`.

Как ведут себя карточки:
- под мышью наклоняются за курсором, по ним скользит блик;
- клик, Enter или пробел выбирает карточку: красная рамка, метка «Selected», остальные две бледнеют; повторный клик снимает выбор;
- свечи на задней карточке рисует скрипт, это украшение.

Уже 1040px три карточки в ряд не помещаются, и ряд становится свайпером:
- лента идёт от края до края экрана, после свайпа карточка встаёт по центру;
- соседние карточки чуть меньше и бледнее и уменьшаются к центральной, их края видны по бокам;
- под лентой три точки, тап по точке листает к своей карточке;
- тап по боковой карточке выдвигает её в центр, тап по центральной выбирает её;
- если пролистать к другой карточке, выбор снимается.

Ширина карточки в свайпере — `--cw` в `partner.css` (78% экрана, от 280 до 380px). Масштаб и прозрачность боковых карточек считает `plan.js` по ходу прокрутки.

Стили — раздел «commission page hero» в конце `partner.css`, поведение — в `plan.js`. Тексты — ключи `cp.earn.*` в `strings/commission/<язык>.json`.

Конкретное время расчёта в блоке не пишем, только «каждый день» (подзаголовок `cp.pay.sub`, третий шаг «Settled daily» с номером 03). Четыре шага выплаты (`cp.pay.t1…4` / `d1…4`) стоят в ряд на бледно-красной линии. Первые два — по новой версии макета (ноябрь 2026): «Clients engage» — «Your referred clients engage with the markets.» (значок: человек и узел связей) и «Commission accrues» — «Commissions from eligible market engagement are tracked in real time.» (значок: две стопки монет); 18 языков. Раз в 1,9 секунды подсвечивается следующий шаг: красная линия с бегущим бликом дотягивается до него (в макете линия серебряная, по просьбе сделана красной), его шарик раздувается в полированную серебряную сферу, иконка краснеет и коротко анимируется (узел связей пульсирует, передняя стопка монет опускается на место, стрелка часов, кошелёк), а над шариком всплывает подсказка: «+1 client» (раньше «+1 trade»), «+$7.50», «Settled», «$0 fees» (ключи `cp.pay.c1`, `c3`, `c4`; «+$7.50» — та же ставка, что в калькуляторе). На планшете шаги 2×2 без линии, на телефоне — по одному, шарик слева от текста.

**Линия на телефоне** (до 560px, ноябрь 2026): шаги там идут столбиком, шар слева от текста, и линия идёт вертикально — от центра первого шара до центра последнего, красная заливка с бегущим бликом доходит до текущего шага, как горизонтальная на десктопе. Шаги разной высоты, поэтому точки меряет `startSteppers` (`--rx`, `--rt`, `--rh`, `--rf` на блоке; заново при изменении размера); для арабского линия справа, по шарам. На планшете (2×2) линии по-прежнему нет.

Оба пошаговых блока (этот и «How to get them» на Partner Tools) ведёт одна функция `startSteppers` в `landing.js`: разметка `[data-stepper]` с шагами `[data-step]`, интервал в `data-every`. Она работает, только пока блок на экране, и каждый раз начинает с первого шага; при «уменьшить движение» сразу показывает последний шаг без анимации. Анимации — классы и прозрачность слоёв, без перерисовки размытия: у шариков нет backdrop-filter.

Чек считает за день, месяц или год: переключатель Day / Month / Year в терминале (`[data-inv-per]`, подписи `inv.pDay`/`inv.pMonth`/`inv.pYear`). От выбора зависят сумма, строка «Rebate on client volume», число лотов, поле PERIOD и подпись над итогом. День — тридцатая часть месяца, год — двенадцать месяцев (`PER` в `startCalculator`).

### Переходы между страницами

**С ноября 2026 анимации логотипа между страницами нет** (по просьбе: она задерживала каждый переход примерно на 1 с — 0,46 с «заливки» до того, как браузер начинал загрузку, и ~0,56 с покрывала поверх уже пришедшей страницы). Ссылки работают как обычные; следующая страница по-прежнему подгружается заранее при наведении, касании или фокусе (`site/assets/js/transition.js`). Покрывало с логотипом, его разметка (`partials/loader.html`), стили, строка `loader` («LOADING») и подписи `data-label` у ссылок удалены при чистке; `transition.js` теперь только подгружает следующую страницу.
